# YuE2 本机生成

## 用户操作

启动服务后，在首页「设置 → 本机模型与资源」准备音乐模型，选择专用空文件夹。首次准备需要网络，安装与下载进入统一队列。准备完成并启用后，在项目内创建音乐片段或完整音乐，填写风格及歌词，提交生成；完成后试听或下载 FLAC。

当前自动安装与实际推理验证于 Apple Silicon Mac，采用专用 Python 3.12、MLX 和固定 YuE2 Studio；不要求用户另装 Python、Git 或 Homebrew。工作台打开、安装准备与启用均不加载模型，只有获准任务按需启动，结束后释放。停止音乐会取消音乐任务并关闭启用状态；历史与音频读取独立于模型。

当前统一任务预约为 14 GiB，并传给固定低内存模式；上游自身的压力检查仍保留。不能将上游“16 GB 最低内存”当成本产品的支持承诺，当前预约在 16 GiB 的默认系统保留策略下不能获准。实际支持与输入长度见[本机模型与资源](model-resources.md)，不提供另一个可以放宽安全额度的 Studio 预算入口。

YuE2 下载约 10 GB 基础权重，另有器乐适配器、Python、依赖、源码及缓存。安装与模型不会嵌入工作台二进制，也不加入 Git。模型许可是 **CC BY-NC 4.0**，YuE2 Studio 代码是 MIT；免费使用的范围与模型许可保持一致。

## 提示词与歌词示例

页面提供 7 个可编辑的示例。点击 **填入** 会替换当前曲名、音乐描述、歌词及生成设置，自动选择对应的人声 / 器乐模式，并设为快速试听；不会自动提交任务。引擎尚未安装时也可以查看和填写示例。

| 类型 | 示例 | 起点 |
| --- | --- | --- |
| 纯音乐 | 钢琴 R&B | 两小节钢琴主题、切分鼓点、贝斯，副歌展开 |
| 纯音乐 | 古筝与钢琴 | 五声音阶、乐器应答、弦乐渐进 |
| 纯音乐 | 松弛爵士 | 电钢琴、低音提琴、刷鼓与旋律变化 |
| 纯音乐 | 轻快律动 | 切分吉他、灵活贝斯、明亮键盘 |
| 带人声 | 中文男声 R&B《夜行信号》 | 温暖男声、钢琴主题，原创中文歌词 |
| 带人声 | 中文女声民谣《风来时》 | 女声、木吉他和轻打击乐，原创中文歌词 |
| 带人声 | 英文女声 City Pop《Morning Light》 | 女声、电钢琴和弹跳贝斯，原创英文歌词 |

**音乐描述** 写风格、情绪、乐器、速度、节奏、旋律特点和段落变化。带人声时再写演唱语言、人声特点和唱法。示例使用英文描述，配有中文说明；可以先改乐器或速度，听过再调整。

**段落结构 / 歌词** 放真正要唱的文字，标签另起一行，例如：

```text
[Verse]
末班车经过路口
晚风吹过我的手

[Chorus]
留一盏灯等风来
让心事慢慢展开
```

带人声示例会取消 **纯器乐** 勾选并展开歌词，后台不加载器乐适配器。纯音乐示例会恢复勾选，并用不带时间的段落标签替换歌词。选择示例后可以继续修改所有字段，后台轮询不会覆盖草稿。

示例是提示词模板，尚未逐一生成试听。模板的界面与提交路径已经验证；具体音乐效果、逐字演唱、音色和精确时长仍以模型生成结果为准。

## 一个目录保存全部引擎文件

默认目录是 `~/Music/YuE2`，可由用户更改。首次安装只接受空文件夹；再次安装只接受已标记为工作台管理的 YuE2 目录，避免覆盖无关文件。

| 子目录 | 内容 |
| --- | --- |
| `bin/`、`python/`、`.venv/` | 专用 uv、Python 和依赖 |
| `source/`、`downloads/`、`requirements.txt` | 固定版本源码、校验过的安装文件及依赖清单 |
| `models/` | 基础模型、VAE、器乐适配器及下载临时文件 |
| `cache/`、`tmp/`、`config/`、`state/` | 包缓存、模型缓存、临时文件及运行设置 |
| `data/` | YuE2 数据库与生成音频 |

Music Room 的作品工作目录只保存指向这个引擎目录的设置 `engines/yue2.json`。基础 MIDI/JSON 作品仍保存在原来的项目目录。安装流程不改全局 Python，不将已有模型复制到每个项目。

安装成功后保存启用状态；重新打开工作台只恢复这个状态，不加载模型或自动恢复旧任务。网页 **停止** 按钮会取消下载或音乐任务，并关闭启用状态。已有安装与模型保留。更换目录前先停止引擎；关闭工作台后可删除整个专用目录回收空间。

下载可重试，已完成模型文件不会重复下载。当前锁定的 Hugging Face 工具在重新启动下载时会重新下载中断的大文件；工作台清理其遗留临时文件，避免重试累积占用空间。运行环境使用固定版本 uv、YuE2 Studio、mlx-Yue，下载归档检查 SHA-256，Python 运行依赖检查锁定哈希；安装器不会运行远程 shell 脚本。

## Agent 的 MCP 接口

复用 Music Room 自带的同一 MCP 配置，无需另配 YuE2 MCP。

| 目的 | 工具 |
| --- | --- |
| 查看目录、日志及模型状态 | `yue2_status` |
| 让用户选择文件夹 | `yue2_choose_directory` |
| 准备文件并启用 | `prepare_yue2(directory, downloadModels)` |
| 启用 / 停止 | `start_yue2`、`stop_yue2` |
| 提交生成 | `yue2_generate(style, lyrics?, preset?, instrumental?, seed?, title?)` |
| 查询 / 取消 | `yue2_get_job(jobId)`、`yue2_list_jobs`、`yue2_cancel_job(jobId)` |

`prepare_yue2` 立即返回，随后轮询 `yue2_status`，只有 `canGenerate=true` 才提交生成。首次模型下载应遵循用户明确选择的目录和下载意愿。

`yue2_generate` 默认 `instrumental=true`、`preset=fast`、`lyrics="[instrumental]"`、`cot=full`，自动组合 AR 器乐 LoRA 与 NAR 音频 LoRA。`lyrics` 也可以写明确的段落结构；使用器乐适配器时按上游建议使用未标注时间的段落标签。生成曲长由模型规划，不能保证描述中的时长精确兑现。

返回 `job.id` 是 32 位十六进制。用 `yue2_get_job` 查询到 `job.status=done` 后，`audioPath` 指向所选目录内的 FLAC；`failed` 会包含失败原因。网页关闭后后台仍生成，重新打开可查看最近任务。任务应通过 Music Room 网页或 MCP 提交，统一队列与预算覆盖整个生成过程。

示例提示词：

> 使用 Music Room MCP，先检查 YuE2 是否就绪。生成一段纯器乐，钢琴主导，有清晰的两小节 riff、切分鼓点和温暖贝斯；主题要有回答与留白，副歌展开，避免机械重复。先用 fast 试听，查询到完成再给我音频路径，不要把排队当作生成成功。

YuE2 输出是音频作品，当前不会自动转成 MIDI，也不会自动成为 MIDI/JSON 乐谱项目中的一个版本。原有 `render_revision/get_job` 是乐谱采样渲染；YuE2 使用独立工具和任务状态。

## 生命周期与验证边界

后端管理一个所属 YuE2 引擎，目录锁防止不同工作台同时使用相同安装。专用工作进程通过标准输入保持父进程租约；工作台取消、退出或租约丢失时停止整个所属计算进程组。不会停止用户自己启动的其他服务。

YuE2 使用随机本机端口，限制 Host/Origin，并在健康检查中核对本次启动的身份及真实引擎状态。主工作台 API/MCP 和音频下载继续采用本机访问令牌。可选引擎设置损坏或硬件不支持不会阻止其他作品功能启动。

以下三轮为 2026-10-08 的 YuE2 历史实施记录；当前统一资源管理按[八轮开发记录](design/model-resource-development.md)验收：

1. 专用目录、安装、状态、进程归属、停止及重启边界。
2. 同一后台能力接入网页与 MCP，完成普通用户操作及接口回归。
3. **真实下载、真实 MLX 生成、音频验证**，再完成独立二进制验证、文档、push 和重启。测试替身只证明边界逻辑，不能代替第三轮推理验收。

开发者可在模型准备完成、普通二进制服务已启动后执行真实验收：

```sh
MUSIC_ROOM_YUE2_REAL=1 \
MUSIC_ROOM_WORKSPACE="$HOME/Music/MusicRoom" \
MUSIC_ROOM_YUE2_DIRECTORY="$HOME/Music/YuE2" \
npm run verify:yue2:real
```

此命令使用官方 MCP 客户端提交真实推理，检查 `fake=false`、完成状态、FLAC 非静音与数值有效性、受保护的音频下载，以及网页实际播放。结果保存到 `test-results/yue2-real/`，不加入 Git。它不会在常规单元测试中自动执行，也不会擅自下载模型。

2026-10-08 已在 Apple M4、32 GiB、macOS 27 上通过真实验收：官方 MCP 调用普通二进制，使用器乐 AR/NAR 适配器和低内存模式，完成 120.799 秒、48 kHz 双声道 FLAC；推理耗时 284.317 秒，音频数值有效且非静音，网页播放时长一致。该记录证明完整生成流程可运行，音乐审美由用户试听判断。模型没有严格遵循提示中的 20 秒长度，精确曲长控制仍需后续设计。
