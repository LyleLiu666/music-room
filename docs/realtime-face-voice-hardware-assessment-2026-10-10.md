# 实时换脸与变声：硬件初步评估

评估日期：2026-10-10。状态：**暂缓，不进入安装、开发或采购。**以后有意愿再恢复评估。

## 结论

拟评估的方案是 **Deep-Live-Cam + w-okada 加载 RVC 音色模型 + OBS**，用于单人实时换脸、变声与直播。

RTX 3060 12GB 可作为这套方案的初步尝试配置；当前 M4 / 32GB Mac 也具备尝试条件。但目前没有运行这套组合，不能确认稳定帧率、显存或内存峰值、音频延迟与长时间运行效果。**“可以尝试”不等于“已证明能流畅直播”。**

暂缓理由：实时画面与声音需要持续及时处理，硬件负载、Mac 加速效果和音画同步仍有不确定性；目前不投入验证。也不据此购买新硬件。

## 方案范围

| 模块 | 职责 | 运行关系 |
| --- | --- | --- |
| Deep-Live-Cam | 用一张参考照片实时换脸，可选人脸增强 | 视频侧主要计算负载 |
| w-okada / RVC | w-okada 加载 RVC 音色模型，实时转换麦克风声音 | 一个实时变声处理环节，不是两个引擎叠加 |
| RVC WebUI | 制作、训练音色模型，也有独立实时界面 | 已有模型时，直播不需要另外启动训练界面 |
| OBS | 合成音视频、编码与推流 | 与换脸、变声同时运行，需要资源余量 |
| MediaMTX | 自建网页观看或音视频转发 | 可选；普通平台直播不必引入 |

**FaceFusion 不属于本次方案。**此前讨论引用的 FaceFusion “8GB 最低、12GB 起更合适”指导，不能作为 Deep-Live-Cam 的硬件要求，已撤回该依据。

## 硬件与判断

### 当前机器：已读取规格，未测试方案

| 项目 | 实际规格 |
| --- | --- |
| 机器 | MacBook Pro，Mac16,1 |
| 芯片 | 基础款 Apple M4 |
| CPU | 10 核：4 性能核、6 能效核 |
| GPU | 10 核集成 GPU |
| 内存 | 32GB 统一内存 |

规格来自本机 `system_profiler SPHardwareDataType SPDisplaysDataType`。

判断：内存条件适合开展初步验证。主要未知项是 Deep-Live-Cam 的 CoreML 加速效果、w-okada 的 RVC 实时处理表现，以及两者与 OBS 同时运行后的持续负载。32GB 统一内存不能直接换算为 12GB 独立显存，也不能据此判断两台机器速度相同。

### RTX 3060 12GB：规划推测

假设使用桌面版 RTX 3060 12GB，配套 CPU 和内存不成为明显瓶颈，单人、单张脸、一个音色、不同时训练或运行大型游戏。

判断：可作为 **720p、目标 25–30 帧、关闭人脸增强**的尝试起点。12GB 显存提供一定容量空间，NVIDIA CUDA 有相应软件支持路径；但没有整套实测，不能承诺达到目标帧率。仅知道显卡型号，也不足以判断完整电脑的表现。

1080p、60 帧、强人脸增强、多张脸、同时游戏，都需要重新评估。当前不提供未经验证的 GPU 占用百分比或逐模块显存数字。

## 资源压力与未验证问题

| 因素 | 对结果的影响 |
| --- | --- |
| 换脸和人脸增强 | 均需处理连续画面；增强是额外负载，初测应关闭 |
| 帧率 | 30 帧要求平均约每 33.3ms 完成一帧；OBS 输出 30 帧不证明换脸生成了 30 个不同画面 |
| 实时变声 | 除模型推理，还受音频缓冲、音高提取、驱动与输入输出链路影响 |
| 同时运行 | 单独运行流畅，不能证明换脸、变声和 OBS 一起运行仍流畅 |
| OBS | 硬件编码可减轻 CPU 压力，场景合成仍需要 GPU 资源 |
| 长时间运行 | 散热、内存增长、掉帧、音频断续与音画漂移都未验证 |
| 网页观看 | 转发主要增加带宽需求；另行转码会增加计算需求，不能混为一谈 |

RVC 官方自带实时界面报告过 170ms 端到端延迟，使用 ASIO 时报告过 90ms，并说明依赖硬件和驱动。**这不是本方案的实测成绩，不能套用于 w-okada + Deep-Live-Cam + OBS，也不能视为当前 Mac 的预期延迟。**

同一条成品直播增加观看人数，主要增加分发负担；多个用户各自实时换脸变声，则增加独立处理负载。例如视频码率设为 6Mbps、100 人直接从服务器观看，视频出站约 600Mbps，尚未计入音频和协议开销。这只是带宽算例。

## 日后恢复时的最小验证

先复用当前 Mac，不提前采购。固定单张脸、单个 RVC 音色、720p、30 帧目标，关闭人脸增强；OBS 使用 Apple 硬件编码。

1. 单独验证 Deep-Live-Cam：记录实际处理帧率、画面质量和内存压力。
2. 单独验证 w-okada / RVC：记录声音质量、输入到输出的实际延迟和断续情况。
3. 两者加 OBS 连续运行至少 30 分钟：检查处理帧率、OBS 渲染与编码掉帧、内存与交换空间、声音断续、嘴型同步及是否越跑越卡。
4. 根据实测判断是否接受画质、帧率和延迟；确有瓶颈后再考虑 NVIDIA 电脑，并在目标配置上复测。

当前没有执行上述验证，没有安装这套工具，也没有形成采购结论。本记录独立于项目现有离线音色转换功能；离线转换的测试成绩不能证明实时方案可用。
