# 播放器歌词

## 使用

打开一个版本，歌词位于音频播放器下方。

- 已保存同步歌词的版本自动展开，播放或拖动进度时高亮当前句并滚动；前奏、间奏和句间空白不高亮。
- 点击歌词跳转到该句；手动滚动后暂停跟随，点击“恢复跟随”继续。
- 点击“收起歌词”隐藏，点击“显示歌词”展开。隐藏不暂停音频。
- “下载 LRC”导出当前版本的同步歌词。校正草稿会明确标注。
- 只有生成时输入歌词的版本显示“参考歌词 · 暂无同步时间”，不虚构时间或提供假的 LRC。

歌词跟随同一个音频播放器，在切换版本后保持后台播放，返回正在播放的版本后恢复原面板。不同版本不共用时间轴。没有同步时间时，点击“生成同步歌词”；已有时间轴可点击“重新生成歌词”。任务显示排队、进度和取消入口，完成后直接在当前播放器展示，无需打开试听页。

## 导入已审阅的时间轴

开发工具接受实验生成的 `alignment.json`，通过正在运行的本地服务核验真实音频 SHA-256 后，写入工作目录的 `lyrics/<versionId>.json`。不会改写原始歌词或音频，也不依赖实验页面运行。

```sh
node scripts/import-lyrics.mjs /Users/liu_y/Music/MusicRoom test-results/lyrics-asr-v9-2026-10-12/alignment.json
```

相同内容可重复导入；存在不同修订时拒绝覆盖。导入后重新打开版本或刷新页面。当前 V9 使用已局部校正的约 2:28.3 起唱时间，仍按校正草稿标识。

## 数据及验证

歌词按版本 ID 和音频路径绑定，存在音频哈希时同时核对。版本进入回收站后禁止读取，恢复后可用，彻底删除时删除歌词；新生成或调速版本不继承旧时间轴。异常文件不输出伪造歌词，界面提供重试。

`npm run verify:lyrics` 验证正式播放器的跳转、间隙、收起展开、跟随、切版与后台播放、LRC 下载和窄屏布局，并验证接口认证、删除恢复和彻底删除。运行前执行 `npm run build`。服务数据验证由 `src/service/studio/lyrics.test.ts` 覆盖。

## 本地自动生成

本机已安装可选歌词引擎。其他 Apple Silicon Mac 需先准备兼容的 Python 环境、Qwen3-ASR-0.6B 和 Qwen3-ForcedAligner-0.6B 模型，再执行：

```sh
node scripts/prepare-lyrics-engine.mjs WORKSPACE VENV ASR_MODEL ALIGNER_MODEL
```

脚本复制本地依赖到工作目录的 engines/lyrics，不自动联网下载；Python 环境仍需兼容本机解释器。未安装时按钮禁用并说明原因。单曲最长 10 分钟；任务进入统一资源队列，以 8 GiB 预算申请资源，模型按任务加载并释放。

先按音频识别，再检索相关参考词作为模型二次识别的上下文，最后定位时间。相邻字片段仅用于检索参考上下文，不直接替换歌词或决定实际唱了多少段；保留音频识别到的重复和新增内容。自动结果仍可能有错字或时间偏差，标为草稿，不能当作已人工校正。

无法定位的内容记录在结果中，并在页面提示数量；无有效时间或未定位内容多于有效行时任务失败。取消、失败或服务重启不会覆盖旧时间轴。成功重新生成前保留旧稿到 lyrics/history；任务状态保存在 lyrics/jobs.json，重启后未完成任务标为中断，可重新生成。

生成流程测试：`node --test src/service/studio/lyrics-generation.test.ts`；分段与参考上下文测试：`python3 scripts/test-lyrics-worker.py`。播放器端到端测试同时覆盖按钮启动、排队、自动刷新和不打断当前播放。
