## 1. 为什么要整体重做

问题不是某个组件，而是同一件事分散在多个地方，各处说法和操作都不一样：

| 事情 | 现在分散在 | 后果 |
| --- | --- | --- |
| 任务进度 | 版本卡片、底部播放条左侧「后台空闲」、播放条展开的队列、任务列表页、设置里的资源区 | 不知道去哪里看、在哪里取消 |
| 本机资源 | 侧栏 CPU/内存表、设置里的大段数字、失败卡片里的解释 | 平时一直占位置，真正要决策时（提交前、失败后）又说不清 |
| 模型准备 | 设置里的「准备模型 / 启用 / 安装」、创作表单底部一行状态、首次使用 | 创作时发现不能用，要去设置里找，再回来 |
| 创作入口 | 新声音弹窗 → 再弹创作窗；再创作 / 修改这版 / 修改要求 / 修改后重试 / 转为器乐 / 修改乐谱 / AI 编曲与导入 / Agent 创作 / 生成音效 / 用音色创作语音 | 入口多、名称不一，每个弹窗各自一套样式 |
| 产生新版本的加工 | 调速常驻在播放器下方；截取、转器乐、改谱、混音在菜单或独立工具里 | 同样「生成新版本」，操作方式各不相同 |
| 删除与恢复 | 版本菜单删除、批量删除；回收站藏在设置弹窗里 | 删了不知道怎么找回 |
| 播放 | 当前版本的浏览器原生播放器 + 底部全局播放条，还被搬进每个弹窗 | 两个播放器并存，弹窗底部多出一条播放器 |

视觉层面：约 15 种字号、同一行 5 种按钮样式、Unicode 字形与 SVG 图标混用、卡片套卡片、大量说明文字代替交互；导航按最近访问排序，页签位置会变。

## 2. 用户、任务与设计原则

**用户**：一个人在自己的 Mac（Apple Silicon）上做声音。生成是重型任务：几分钟到几十分钟，占 5–14 GiB 内存，逐项排队。

**核心任务（按频率）**

1. 描述 → 生成 → 试听 → 再改 → 选成品（创作循环）
2. 比较几个版本，标记成品 / 灵感
3. 等生成时去做别的：排更多任务、切项目、听别的
4. 使用成品：下载、在声音库连续播放、整理播放列表
5. 管素材：参考音色、外部导入
6. 了解并控制本机：能不能跑、为什么在等、暂停 / 取消 / 释放、准备模型
7. 维护：回收站、备份、Agent 连接、模型目录与日志

**设计原则**

1. **一件事一个主场**：每类信息只有一处完整呈现，其他地方只放一行摘要并能跳过去。版本的结果与进度在版本行；全局队列与资源在「任务与资源」；配置在「设置」。
2. **先说能不能，再让填**：创作面板底部先告诉用户这种声音能否在本机生成，不能时只给一个下一步（准备模型 / 启用 / 查看内存）。
3. **凡是产生音频，都是新版本**：生成、修改、保存调速版、截取、转为器乐、修改乐谱、保存混音、音色转换，都在同一个右侧面板里完成。结果都作为新版本出现在列表顶部，原版不变。
4. **常用的直接放，不常用的收起来，但名称要说清楚**。
5. **状态看得见，出错只给一个主动作**，原因用一句话，技术细节折叠。
6. **日间和夜间同样完整**，所有颜色都走 token。

## 3. 对象与信息架构

对象模型不变：**项目 → 声音（音乐片段 / 完整音乐 / 语音 / 音效 / 音色转换）→ 版本**。版本可标「成品」（每个声音一个）和「灵感」（多个）。全局资产：音色、外部导入音频、播放列表。后台：任务（生成、加工、准备模型、导入、同步歌词）。

```text
侧栏
├─ 项目（列表，＋新建）
├─ 声音库
├─ 音色库
├─ 任务与资源        ← 实时一行状态：空闲 / 1 生成中 · 2 排队 / 已暂停 / 等待内存
└─ 底部：本机状态一行（内存）· 日夜切换 · 设置

主区页面（一次一个）
├─ 项目页：声音页签 + 当前版本 + 版本列表
├─ 声音库：全部声音 / 播放列表
├─ 音色库
├─ 任务与资源：本机资源 + 进行中与排队 + 历史
└─ 设置：模型 / 内存与资源 / 回收站 / 备份与恢复 / Agent 连接 / 外观 / 关于

右侧面板（非模态，同时最多一个，不挡住主区）
├─ 新声音（选类型 + 名称 → 直接接着填第一版）
├─ 再创作 / 修改这版（按声音类型）
├─ 加工：保存调速版 / 截取 / 转为器乐 / 修改乐谱 / 音色转换
├─ 版本信息：创作要求 / 生成记录 / 来源
├─ 音色详情 / 新增音色
├─ 生成音效（声音库）
└─ 项目成品

居中确认框（模态，只放短操作）
└─ 新建项目 / 重命名 / 删除确认 / 彻底删除确认 / 复用参数确认

全屏工具
└─ MIDI 与音轨（覆盖主区与面板，顶部常显 项目 / 声音 / 版本 与关闭）
```

去掉：侧栏 CPU/内存表、侧栏项目分页、右上角浮动的日夜切换、设置弹窗、回收站弹窗、底部播放条里的任务摘要、弹窗里的播放条。

## 4. 关键流程

### 4.1 首次使用（空工作区）

主区直接显示「从一个声音开始」：5 种类型的选择块 + 项目名 + 声音名，提交后进入该声音并打开创作面板。内容与「新声音」面板第一步一致，只是平铺在主区。保留「只创建项目」文字按钮。

### 4.2 新声音 → 第一版（一个面板走完）

1. 项目页点「＋ 新声音」（页签行末尾），打开右侧面板「新声音」。
2. 第一步：类型（5 个单选块，带一句说明）+ 名称（必填，回车可提交）。按钮「下一步」。
3. 点「下一步」时创建声音，面板原地切换为该类型的创作表单，标题变为「第一版 · 名称」，页签行出现新声音并选中。
4. 提交后面板关闭，版本列表顶部出现「排队中 / 生成中」的新版本行，并提示「已加入队列，前面 n 项」。

空项目的主区与第一步内容相同；从主区开始时，面板直接进入第二步。

### 4.3 再创作 / 修改这版

- 「再创作一版」（页签行右侧，唯一墨黑主按钮）：基于当前声音的草稿；没有草稿时带入当前版本的要求。面板副标题写「基于 V2「…」」。
- 「修改这版」（当前版本操作行，或版本行菜单）：带入该版本的原始要求，并记录来源。
- 失败版本行的「修改要求」打开同一个面板。
- 面板打开时，左侧版本列表仍能播放和切换，用户可以边听边写。切换版本不会改动面板内容；切换声音时，面板跟着换成该声音的草稿，标题同步。
- 草稿随声音保存（沿用 `StudioDraftStorage`）。保存状态显示在面板底栏「草稿已保存 · 18:06」，保存失败时在原位置显示红字原因。

### 4.4 试听、比较、挑选

- 点版本行的播放键：该版本成为当前版本并开始播放。点版本行其他位置：只切换当前版本，不自动播放。
- 当前版本区：播放 / 暂停、拖动波形定位；`空格`播放 / 暂停，`↑` / `↓` 切换版本（焦点不在输入框时）。
- 「对比两版」：版本行出现复选框，选够两项后，当前版本区换成 A/B 对比条（两条波形，A 和 B 切换时保持播放位置，替代现在的比较弹窗）。退出对比回到正常模式。
- 「选择」：批量模式，出现复选框和底部操作条（删除所选 n 项、取消），替代常驻的「全选」与说明文字。
- 「选为成品」「留作灵感」是切换按钮；成品在版本行显示朱红印章，灵感显示朱红描边印记。

### 4.5 加工生成新版本

当前版本「更多」菜单分组如下：

| 分组 | 项目 | 行为 |
| --- | --- | --- |
| 试听 | 调速试听…、试听结尾、生成同步歌词 / 显示歌词 | 调速试听在播放器下方展开调速条（0.5–2.0 倍、0.8 倍、原速），条内有「保存调速版」，进入加工面板确认 |
| 加工 | 截取…、转为器乐演奏…、修改乐谱…、MIDI 与音轨 | 前三项打开右侧加工面板；MIDI 与音轨打开全屏工具 |
| 导出 | 下载 WAV / 原文件 / MIDI / LRC；转换版本另有原音 / 转换人声 | 只列当前版本实际有的格式，没有的不显示 |
| 信息 | 创作要求、生成记录 | 打开右侧「版本信息」面板 |
| — | 删除这版 | 居中确认，完成后提示「已删除 V3 · 撤销」 |

加工面板与创作面板骨架相同：标题「截取 · V2」，正文为参数，底栏写「生成为新版本，原版保留」并放主按钮。

### 4.6 生成中、排队、失败（版本行内）

| 状态 | 版本行显示 | 动作 |
| --- | --- | --- |
| 排队 | 「排队中 · 前面 n 项」；队列暂停时显示「队列已暂停」 | 取消 |
| 等待内存 | 「等待内存 · 需约 14 GiB，现在可用 11.0 GiB」（字段来自准入明细） | 取消；链接「查看本机资源」 |
| 加载 / 运行 | 5 段阶段条 + 「2 / 5 生成音乐内容 · 12 / 32」+ 已运行时长；长时间无进度时撤下估计，单独提示 | 取消 |
| 失败 | 标题一句（沿用 `resourceFailure` 的标题）+ 一句建议 | 主动作：重试 / 继续生成；次动作：修改要求；「技术详情」折叠 |
| 中断 / 已取消 | 「已中断，可从 规划 / 合成 继续」 | 继续生成 / 修改要求 |
| 仅乐谱 | 「乐谱已保存，尚无音频」 | 生成试听音频 |

当前版本区若为上述状态，显示同样的信息并放大一级；不出现空的播放器。

### 4.7 本机资源与模型（重点）

**平时**：侧栏底部只有一行，例如「内存 正常 · 可用约 11.0 GiB」加 5 格小条。点击进入「任务与资源」。

| 状态 | 侧栏一行 | 颜色 |
| --- | --- | --- |
| 正常 | 内存 正常 · 可用约 X GiB | 次级文字色 |
| 偏高 | 内存偏高 · 新任务会等待 | 警示色（赭） |
| 过高 | 内存过高 · 已停止重型任务 | 危险色 |
| 读取失败 | 暂时无法读取内存 | 危险色 |

**提交前**（创作 / 加工面板底栏，左侧状态行，按优先级只显示最重要的一条）：

1. 模型未准备：「语音模型尚未准备」+ 按钮「准备模型」，就地开始，进度显示在同一行和任务页。
2. 音乐未启用：主按钮变为「启用并生成」，先启用再提交；启用失败时停在面板并显示原因。
3. 本机额度永远不够（应用上限低于该引擎预约）：「这台电脑的内存额度不足以运行音乐（需约 14 GiB，上限 11.2 GiB）」，主按钮禁用，链接「查看原因」→ 设置 · 内存与资源。
4. 有其他任务：「前面有 n 个任务，提交后排队」。
5. 内存偏高：「内存偏高，提交后会等待」。
6. 就绪：「YuE2 已就绪」。

第 3 条要用到各引擎的启动预约，这些预约见[模型与资源](../model-resources.md)。「需要后端配合」一节有说明。

**运行中**：版本行按 4.6 显示；侧栏「任务与资源」右侧实时显示「1 生成中 · 2 排队」。

**任务与资源页**（第 5.5 节）是唯一完整呈现资源和队列的地方：内存分布条、模型驻留与释放、暂停 / 恢复后续任务、逐项取消、历史。

**设置 · 模型**：集中安装、启用、停止、目录和日志，不负责日常创作时的就地准备。

### 4.8 声音库播放

沿用现有规则（服务端分页、确定队列、随机一轮不重复、刷新恢复不自动出声）。界面上：列表行播放键从该条开始；「播放全部」+ 播放方式菜单；底部播放条（dock）只在本次会话播放过声音后出现，显示来源与上一首 / 下一首 / 方式 / 队列。

### 4.9 音色

音色库列表 + 右侧「音色详情」面板（试听原音 / 处理后、常用、清理、重命名、删除、「用这个音色创作语音」）。「新增音色」也用右侧面板。语音创作面板里选音色时，可以就地上传，并有链接「管理音色」跳到音色库。

### 4.10 删除与恢复

- 删除版本 / 声音 / 项目 / 音色：居中确认（项目和声音写明包含的声音与版本数），完成后底部提示「已删除 … · 撤销」，8 秒内可点撤销（调用恢复）。
- 回收站在「设置 · 回收站」，规则不变（父级恢复、彻底删除二次确认、清空）。
- 正在生成的内容不能删除，确认框直接说明并给「去取消」。

### 4.11 设置

是一个页面，不是弹窗。左侧小节导航，右侧内容，详见 5.7。

## 5. 页面规格

尺寸单位为 CSS px，均指 1440 × 900 下的默认值。

### 5.1 侧栏（rail）

- 宽 232，背景 `--paper-sunk`，右侧细线。
- 字标「Music Room」衬线 20/28。
- 项目搜索框与「＋」新建按钮同排常驻（新建为居中确认框）。列表完整列出并在列表内滚动，不分页；搜索无结果时显示「没有匹配的项目」。项目行高 34，当前项加深底色并用 500 字重，右侧灰色数字为声音数（0 不显示）。从其他页面点回当前项目时，回到原来的声音与版本。
- 间隔 32 后为三个全局入口，均为 16px 线性图标 + 文字。「任务与资源」右侧显示实时状态（空闲时不显示）。
- 底部：本机状态一行（4.7）；一行两个按钮：日夜切换（图标，`aria-label` 写当前目标「切换到夜间」）与「设置」。
- 窗口宽 ≤1360 且面板打开时收为 64 宽图标条：项目显示为首字方块（衬线 13，当前项墨底），全局入口只留图标，实时状态变为小圆点，本机状态隐藏。

### 5.2 页头（所有主区页面统一）

标题衬线 28/36（≤ 720 时 20/28），下方一行元信息 13/20 次级色。右侧最多一个主按钮加若干线框或文字按钮，与元信息底边对齐。不使用眉标题和副标题段落。

| 页面 | 标题 | 元信息 | 右侧 |
| --- | --- | --- | --- |
| 项目 | 项目名 | n 个声音 · n 个已选成品 · 保存在本机 | 项目成品 n、⋯（重命名 / 删除项目） |
| 声音库 | 声音库 | 选为成品或留作灵感的声音自动收录 · n 个声音 | 生成音效、导入音频 |
| 音色库 | 音色库 | 参考声音，所有项目共用 · n 个音色 | 新增音色（主） |
| 任务与资源 | 任务与资源 | 生成在本机后台进行，关闭网页不会中断 | 暂停 / 恢复后续任务 |
| 设置 | 设置 | 工作目录路径（可复制） | — |

### 5.3 项目页

自上而下：页头 → 声音页签 → 当前版本 → 全部版本 → 其他创作方式。

**声音页签**：按创建顺序排列，**不随访问改变**。每个页签为「名称 + 小字 类型 · 版本数」。超出宽度时，末尾显示「更多 n」下拉（带搜索，沿用现有溢出组件），当前声音若在溢出中，就暂时显示在可见区最后一位。页签行末尾放「＋ 新声音」，最右放主按钮「再创作一版」（没有版本时为「开始创作」，面板打开时变成按下状态「正在创作…」）。声音的重命名 / 删除放在当前页签悬停出现的 ⋯ 和页头 ⋯ 中。

**当前版本**（不用卡片，靠留白分区）：
- 第一行：「V2」衬线 24、印记、右侧元信息（类型 · 参数 · 时间），12 次级色。
- 第二行：创作要求摘要，用「」括起，衬线 17/28 次级色，最多两行。语音显示正文第一句；转换显示「来源 → 目标音色」。
- 播放器：48 墨色圆形播放键 + 波形（高 56，已播部分墨色，未播部分浅色）+ 下方两端时间（12，等宽数字）。点击 / 拖动波形可定位。波形来自音频解码后的峰值（前端 `AudioBuffer` 下采样，按版本缓存）；解码前显示浅色细线占位。
- 操作行（与波形左缘对齐）：选为成品 / 留作灵感（线框切换）| 修改这版、下载（文字按钮）| 右侧「更多 ▾」。
- 歌词：有歌词的版本在操作行下方显示折叠条「歌词 · 已同步 / 参考词未同步」，展开后为现有歌词组件。

**全部版本**：标题「全部版本 n」衬线 16，右侧「对比两版」「选择」。行高 56，行间细线，当前行底色 `--paper-select`。列：播放键（28 圆形线框，正在播放时为墨底）· 版本号（衬线）· 描述（单行省略，下方可选 12 小字：语音为音色 · 情绪，音乐为目标时长）· 小波形（120 × 20）· 印记 · 时长 · 行菜单 ⋯（悬停或当前行显示）。状态行见 4.6。转换版本保留分页。

**其他创作方式**：音乐类为一句话「也可以 复制给 AI 的编曲要求 交给已连接的 Agent，或 导入 MIDI / JSON 作为新版本」；语音类为「复制给 Agent 的语音要求」。两个链接分别打开面板中的对应小节。

### 5.4 右侧面板（创作 / 加工 / 详情）

- 宽 452，语音创作用宽型 600。背景 `--paper-raised`，左侧细线，无阴影；面板打开时主区宽度相应减小（不叠在上面）。
- 结构：头部（标题衬线 20/28 + 副标题 12 + 关闭）→ 正文滚动区 → 底栏（左状态行 12/18，右主按钮 40 高）。
- 正文用细线分节，节标题 13/500，**不用卡片背景**。每节最多一行 12 号提示；更多解释收进「怎么写？看示例」之类的链接或折叠行。
- 折叠行：高 48，左侧名称，右侧当前取值摘要（如「未填写」「随机种子」），点开后就地展开。
- `Esc` 关闭面板（先关菜单，再关面板）；`⌘ / Ctrl + Enter` 提交。
- 各类型字段：

| 类型 | 字段（按顺序，不常用的折叠） |
| --- | --- |
| 音乐 / 片段 | 作品形式（纯音乐 / 带歌词演唱）· 音乐风格（多行，示例链接）· 歌词（带歌词时出现，示例可填入）· 目标时长（1–5 分 / 由模型决定，片段另有短档）· 折叠：乐谱与段落结构（结构、ABC）· 折叠：生成设置（随机种子、较快尝试）· 折叠：交给 AI 编曲（复制要求） |
| 语音 | 参考音色（下拉 + 试听 + 就地上传 + 管理音色链接；Breeze 参考文字稿折叠）· 要说的话（大文本框、导入 TXT、字数 / 8000）· 情绪强度（5 档分段）· 折叠：情绪描述 |
| 音效 | 描述 · 时长（1–5 秒分段）· 保存到（声音库 / 当前项目）· 折叠：随机种子 |
| 音色转换 | 音频来源（上传 / 已有声音：项目 → 声音 → 版本，带试听）· 目标音色 · 整体升降调（默认不升降调；「怎么判断是否合适？」折叠）|
| 加工 | 截取：起止秒、淡入淡出；调速：倍数（从调速条带入）；转为器乐 / 修改乐谱：沿用现有字段 |

### 5.5 任务与资源页

1. **本机资源**（页头下第一块，无卡片背景，上下细线）：

   - 一行文字：「内存压力 正常 · 采样 18:05:55」。

## 12. 需要后端配合 / 不在范围 / 风险

**需要后端配合**
- 提交前的准入预检（4.7 第 3 条）：前端需要各引擎的启动预约，或一个只读预检接口（建议 `resource_estimate {engine, input}` 返回与准入相同的 `Admission`，不排队、不加载模型）。接口提供前，第 3 条只在已知该引擎预约必然超出应用上限时显示（数值取自服务端返回，不在前端硬编码）；做不到就先不显示，不能猜。
- 「等待内存」行内的需求 / 可用数字取自 `ResourceTaskState.admission.details`；如果版本数据里拿不到，需要在 `backgroundVersions` 中带上。

**不在范围**
- 封面、文生图（见 studio.md）；音频转 MIDI；系统辅助功能专项。
- 后端数据格式、MCP 工具、资源策略和阈值。

**风险**
- `app.ts` 是 11 万字节的单文件闭包，P3 / P4 需要先把渲染函数拆成按区域的小模块（`rail.ts`、`project-page.ts`、`version-list.ts`、`panel.ts`、`settings-page.ts`、`tasks-page.ts`），再改结构，避免一次性大改。
- 约 30 个浏览器测试文件依赖弹窗和文案，P2 / P4 改动最大。每期都要先跑一遍，记录哪些旧断言失效，再逐条改成新行为的断言。
- 自绘播放器要覆盖原生控件的能力：播放 / 暂停、定位、时间、读取失败后「重新读取」、加载中状态。
