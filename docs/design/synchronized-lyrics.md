# LRC 歌词与同步播放

状态：已接入正式播放器的显示、滚动、下载与参考词回退；自动分析和人工编辑仍为设计方案。已校正的 V9 时间轴通过校验音频后导入。当前操作见[歌词使用说明](../lyrics.md)。本文后续生成方案不代表已实现。更新时间：2026-10-12。

## 1. 结论与目标

用户希望生成 LRC 歌词，并在播放歌曲时同步滚动。完整实现属于较复杂的音频处理功能：播放器展示相对简单，主要工作是根据实际演唱生成可信的逐句时间轴。先验证对齐效果，再开发完整功能；不能用歌曲时长平均分配时间点来冒充同步歌词。

已按用户要求使用 6 首现有生成歌曲完成本地对齐试验，并提供独立滚动试听页。4 首出现明显时间异常，不能直接自动发布；详见[真实歌曲试验记录](../lyrics-alignment-trial-2026-10-12.md)。正式运行功能未改动。

后续 V6 的 [ASR 辅助对照](../lyrics-asr-trial-2026-10-12.md)将整句无效时间从 12 句降为 0 句，50 句原词均分配了时间，但这不证明它们实际全部被唱出；其中原词与片段对应关系由助手审阅，尚未完成逐句人工听评或全自动实现。

V9 已按用户澄清验证“句中文字用参考词纠错、段落结构按音频记录”，见 [V9 试验](../lyrics-asr-v9-trial-2026-10-12.md)。未发现额外整段，但尚未以含额外整段的已确认样本验收。

## 2. 用户体验与范围

以下为建议方案，自动执行时机及首版范围待确认。

### 2.1 首版建议

以本项目生成、已经保存歌词的演唱版本为入口，提供「生成同步歌词」。旧版本也可以主动补生成。任务后台执行，音频仍可试听和下载；失败不影响歌曲生成状态。

生成后在播放器下方显示歌词，当前句高亮并滚动到可见位置。暂停时停止推进，拖动进度、重新播放和切换版本后立即按当前音频时间更新。歌词只在自身区域滚动，不推动整页；用户手动浏览时暂停自动跟随，提供恢复跟随入口。

提供「下载 LRC」，默认与音频使用相同的标题和版本号。支持整体时间偏移及逐句时间校正，另存歌词修订，不改变生成时填写的原始歌词。重新分析不得直接覆盖人工校正结果。

无时间轴时展示普通歌词，并明确尚未同步；没有歌词时不虚构歌词。纯音乐不自动发起分析。以明确的作品类型和用户操作决定入口，不通过匹配风格描述中的词语判定是否有演唱。

### 2.2 暂不纳入首版

- 卡拉 OK 逐字着色、多语言翻译与多人对唱分栏。
- 没有原歌词的外部歌曲自动识词、音色转换结果自动继承歌词。
- 歌曲生成成功后默认自动分析所有作品，或批量处理历史作品。
- 将歌词嵌入 MP3 标签。

以上只是控制实施范围的建议，不是对用户需求的否定。第一轮效果验证通过后再确认是否扩展。

## 4. 时间轴生成方案

### 4.1 分析流程

**已对应上的句子以参考歌词纠正 ASR 错字；实际唱了哪些段、顺序和重复次数以音频为准。** 用户已明确，主要风险是音频比原词多唱一整段，而不是让 ASR 的同音错字覆盖已知歌词。原始输入与实际演唱时间轴分别保存。

- 已确认对应关系的句子使用参考词，包括“压弯万丈星光”“自由惯了的人”等容易被 ASR 识错的内容。
- 多唱已有段落时，按每次实际出现分别记录；不能因为原词只写过一次就丢掉重复段。
- 多唱原词之外的新段落时，保留独立的识别候选和音频位置，允许没有原词关联；不强行套进最相似的原词。
- 漏唱、换序和半句按音频记录；未确认的段落关系标为待校正，不能强迫每句原词都进入时间轴。
- ASR 用来发现演唱结构和额外段落，不单独决定已匹配句子的字词；新段落的识别内容和所有时间仍需听评。

1. 读取指定版本的原音频、原歌词及音频校验值，保存不可变任务输入。
2. 优先验证先识别实际演唱结构、审阅段落对应关系、用参考词纠正已匹配句子、再对每次演唱分段对齐的方案。整曲强制匹配原词仅保留为实验基线。如伴奏明显影响效果，再验证提取人声后对齐的收益和成本。
3. 对齐结果记录每句的开始、结束、原歌词对应关系，以及无法确认的位置。实际漏唱、重复或唱词变化必须能够表示，不能强迫每句都得到时间点。
4. 检查时间合法、顺序合理、没有超出音频长度，并结合人工听评判断质量。模型分数只能辅助检查，不能单凭分数宣称准确。
5. 保存分析结果。局部无法确认时标为「待校正」，不把缺失句随机安插到时间轴中。

不能用文本相似、关键词碰撞或字符串包含关系替代对实际演唱内容的判断。若候选技术本身无法识别漏唱和重复，应明确限制，并在该类作品上保留待校正状态。

### 4.2 数据与生命周期

建议由歌词服务负责时间轴、任务和导出，播放器只负责显示。持久化字段至少包括：

- 所属版本 ID、音频校验值、原歌词校验值、分析引擎版本。
- 歌词修订号、来源（自动分析／人工校正）、更新时间。
- 每个实际演唱片段的文本、开始和结束时间、可选原词关联、识别证据及待校正原因。原词关联允许一对多、多对一或无关联，不要求逐行一一对应。
- 原词的已关联、确认未唱或待确认状态，与演唱片段分别保存。
- 任务状态：排队、分析中、待校正、就绪、失败、取消、中断。

旧数据缺少歌词记录时按未生成处理，不批量迁移或自动启动任务。任务重复提交应复用同一请求；写入须原子完成，崩溃后不能发布半份歌词。回收站隐藏对应歌词，恢复后可再次使用，彻底删除时清理附属记录。分析过程中删除版本，应先取消任务或阻止删除。

重试保留先前可用修订，只有新结果成功保存后才切换。音频或歌词输入变化时使旧分析失效；音频只换下载格式不创建新的作品歌词。

### 4.3 LRC 与播放器的区别

内部保存开始和结束时间，播放器在前奏、间奏和结尾的无演唱区间取消当前句高亮。不能让上一句一直亮到下一句开始。

LRC 导出采用 UTF-8 和 `[mm:ss.xx]歌词` 形式，重复演唱按每次出现的时间导出。导出前验证时间非负、单调和不超时长；百秒分舍入造成同一时间标签时应有明确处理规则。内部的待校正说明不混进歌词正文。

普通 LRC 主要表达起始时间，不能完整承载内部结束时间、审核状态等信息。间奏是否导出空白时间标签，需通过目标外部播放器兼容性验证后决定。未确认时间的句子不得伪造时间；存在这类句子时优先引导校正，并明确下载的是否为不完整草稿。

MP3 编码可能引入起始偏移，应实测同一 LRC 在原文件、本应用播放器和导出 MP3 上的同步表现，必要时按导出音频修正偏移，不能只验证文件能打开。

## 5. 播放及衍生版本规则

- 按音频的 `currentTime` 选择当前句，不能用独立计时器累加，避免暂停、跳转和后台标签页造成漂移。
- 版本切换和慢请求返回时核对版本与修订，避免上一首歌词覆盖当前曲目；刷新歌词不得重新创建正在播放的音频元素。
- 背景播放、项目试听、声音库试听使用同一版本时间轴。首版是否同时展示多个位置待确认，但不得串词。
- 临时调整播放速度继续使用音频当前时间，无需再缩放歌词。
- 保存为固定倍速的新音频时，若验证只有整体速度变化，时间点按倍速反向缩放并绑定新音频；剪切、重新生成或无法证明时间关系的处理不能直接复用。
- 长歌词使用有限的展示区域，支持键盘操作及减少动画偏好，不将每次播放进度都朗读给辅助工具。

## 6. 分阶段实施与验收

### 6.1 先验证对齐，作为开工门槛

建立经用户同意使用的真实歌曲样本集，覆盖中文演唱、长前奏、间奏、重复副歌、拖长音、漏唱、歌词与演唱不同，以及歌曲被截断。每条记录音频、参考原词、人工听评确认的实际唱词及起止时间、工具版本、耗时和峰值内存。覆盖率以实际演唱为分母，不以原词保留率作为成功指标。

先比较少量候选方案，不在本文锁定具体依赖。需要安装新模型时，先明确来源、许可证、大小、运行目录和资源需求。提取人声只在实验显示收益后加入正式链路。

建议准确性门槛（待商榷）：可确认的演唱行中至少 95% 的起始时间误差不超过 0.5 秒，另报最大误差、正确匹配行覆盖率、漏唱和重复处理情况。不能通过丢弃难对齐的句子提高通过率。若不达标，保留人工校正或暂缓自动生成，不发布看似同步的结果。

### 6.2 再实现保存、展示和导出

先写失败用例，再实现对应行为：

| 层级 | 必须验证的结果 |
| --- | --- |
| 演唱与参考词差异 | 漏唱不补造、重复按次数保留、已匹配句用原词纠错、新增整段允许无关联、换序与半句按实际演唱、识别冲突标为待确认 |
| 时间轴与 LRC | 空数据、非法时间、重复句、分钟进位、舍入、中文编码、偏移后负时间、结束间隙 |
| 服务 | 认证、历史版本读取、请求去重、资源排队、取消、重启、失败重试、原子保存及删除恢复 |
| 播放器 | 首句前不高亮、间奏停止高亮、暂停、快进后退、结束重播、切歌、迟到请求、后台播放和手动滚动 |
| 数据关联 | 新音频不误用旧歌词、人工修订不被覆盖、声音库与项目一致、变速副本同步 |
| 真实效果 | 对照人工标注核验起止时间，在实际 MP3 上试听，并验证外部播放器读取 LRC |

界面测试使用预设时间轴只能证明滚动行为，不能证明自动对齐准确。发布必须分别给出界面、服务和真实音频的验证结果。

## 7. 待确认事项

1. 首版是否先支持「有原歌词的生成歌曲」，由用户主动点击生成同步歌词。
2. 是否接受本地新增分析模型；具体安装体积、耗时和资源预算等实验后确认。
3. 准确性门槛、待校正交互，以及 LRC 草稿是否允许单独下载。
4. 原版播放器、声音库和背景播放的歌词展示优先级；后续是否支持外部歌曲自动识词。
