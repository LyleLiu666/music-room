# 播放器歌词

## 使用

打开一个版本，歌词位于音频播放器下方。

- 已保存同步歌词的版本自动展开，播放或拖动进度时高亮当前句并滚动；前奏、间奏和句间空白不高亮。
- 点击歌词跳转到该句；手动滚动后暂停跟随，点击“恢复跟随”继续。
- 点击“收起歌词”隐藏，点击“显示歌词”展开。隐藏不暂停音频。
- “下载 LRC”导出当前版本的同步歌词。校正草稿会明确标注。
- 只有生成时输入歌词的版本显示“参考歌词 · 暂无同步时间”，不虚构时间或提供假的 LRC。

歌词跟随同一个音频播放器，在切换版本后保持后台播放，返回正在播放的版本后恢复原面板。不同版本不共用时间轴。没有同步时间时，点击“生成同步歌词”；已有时间轴可点击“重新生成歌词”。任务显示排队、进度和取消入口，完成后直接在当前播放器展示，无需打开试听页。

底部状态栏展开“后台任务”，可查看每项歌词任务所属歌曲和版本。正在执行的任务显示模型加载、演唱段落识别、时间定位或校验保存步骤，以及已处理段数、百分比、已运行时间和最近推进时间；排队任务显示前面还有几项。切换页面、打开弹窗后仍可查看。百分比按已处理音频分段估算，不代表耗时比例；模型加载期间显示进度待定。超过两分钟没有新进度会提示仍在等待，不能据此认定任务失败。

## 导入已审阅的时间轴

开发工具接受实验生成的 `alignment.json`，通过正在运行的本地服务核验真实音频 SHA-256 后，写入工作目录的 `lyrics/<versionId>.json`。不会改写原始歌词或音频，也不依赖实验页面运行。

```sh
node scripts/import-lyrics.mjs /Users/liu_y/Music/MusicRoom test-results/lyrics-asr-v9-2026-10-12/alignment.json
```

相同内容可重复导入；存在不同修订时拒绝覆盖。导入后重新打开版本或刷新页面。当前 V9 使用已局部校正的约 2:28.3 起唱时间，仍按校正草稿标识。

## 数据及验证

歌词按版本 ID 和音频路径绑定，存在音频哈希时同时核对。版本进入回收站后禁止读取，恢复后可用，彻底删除时删除歌词；新生成或调速版本不继承旧时间轴。异常文件不输出伪造歌词，界面提供重试。

`npm run verify:lyrics` 验证正式播放器的跳转、间隙、收起展开、跟随、切版与后台播放、LRC 下载和窄屏布局，并验证接口认证、删除恢复和彻底删除。运行前执行 `npm run build`。服务数据验证由 `src/service/studio/lyrics.test.ts` 覆盖。

## 本地自动生成

本机已安装可选歌词引擎。其他 Apple Silicon Mac 需先准备兼容的 Python 环境、Qwen3-ASR-0.6B 和 Qwen3-ForcedAligner-0.6B 模型，再执行：

```sh
node scripts/prepare-lyrics-engine.mjs WORKSPACE VENV ASR_MODEL ALIGNER_MODEL
```

脚本复制本地依赖到工作目录的 engines/lyrics，不自动联网下载；Python 环境仍需兼容本机解释器。未安装时按钮禁用并说明原因。单曲最长 10 分钟；任务进入统一资源队列，以 4 GiB 启动预约申请资源，模型按任务加载并释放。运行保护最高 8 GiB，并受应用剩余额度约束；该保护值不预占内存，也不作为启动所需额度。系统内存压力检查仍独立生效。

2026-10-22 在 Apple M4 / 32 GiB 上完成内存校准：两首真实歌曲、重复运行及一段重复拼接的 10 分钟输入，识别和定位共 8 个阶段全部完成，模型进程的系统记账内存观测峰值为 3.84 GiB。按用户选择将启动预约设为 4 GiB，独立保留最高 8 GiB 的运行保护。4 GiB 接近本次峰值，不能视为所有歌曲或其他设备的最低需求，见[内存实测记录](evidence/lyrics-memory-calibration-2026-10-22.json)。

正式流程为：本地分段语音识别 → 配置的大模型两轮原词核对 → 本地时间定位。参考段落召回保留原顺序、中间句和重复行；相邻字片段仅用于检索排序。27B 根据发音和上下文返回原词行号或半句引用，程序校验引用与识别片段覆盖；两轮一致的匹配才使用原词。分歧、新增和无法确认的句子保留识别原文，提示待试听确认。核对后重新定位时间。自动结果仍标为草稿，不能当作已人工校正。

### 配置自己的大模型账号

歌词核对优先使用 Cloudflare 免费预算；本机预算不足或 Cloudflare 返回 429（额度或容量限制）时，自动使用 OpenAI Chat Completions 兼容备用接口。备用服务会重新执行两轮核对，不混用两个服务的结论。网络错误、截断或无效核对结果不触发切换。

备用接口在用户目录创建 `~/.config/music-room/lyrics-review.env`（文件权限设为 `600`）：

```dotenv
LYRICS_REVIEW_BASE_URL=http://你的服务地址:端口/v1
LYRICS_REVIEW_API_KEY=自己的密钥
LYRICS_REVIEW_MODEL=modelscope/Qwen3.8-27B
```

接口地址可填根地址或以 `/v1` 结尾的地址。配置任一字段后必须补齐三项；备用接口配置错误或调用失败会明确报错。兼容接口不使用 Cloudflare 的本机 Neurons 预算，其用量限制由该服务决定。两轮请求在一次核对中使用同一份配置，缓存按接口、模型和输入隔离。

主服务使用 Cloudflare Workers AI 的 `@cf/qwen/qwen3.8-27b`。在用户目录创建 `~/.config/music-room/cloudflare-ai.env`（已有配置可继续使用）：

```dotenv
CLOUDFLARE_ACCOUNT_ID=自己的账号ID
CLOUDFLARE_API_TOKEN=自己的令牌
```

也可通过启动服务时的同名环境变量提供，环境变量优先于文件。配置文件每次核对时重新读取；修改启动环境变量需重启服务。凭据保存在用户目录，不随程序打包或写入项目仓库；只由本地服务用于调用所配置的核对接口。未配置时，歌词生成按钮显示不可用原因。使用者还需按上文准备本地识别和时间定位引擎。

Cloudflare 的本机每日核对预算上限为 9,500 Neurons，北京时间早上 8 点重置；请求前预留预算，收到用量回执后结算，超时请求保留预留额。跨日回执不会从新一天的计数中扣掉前一天的预约；已知用量保守地记入回执当日。系统时钟回拨或计数文件损坏时停止请求，避免错误放大可用额度。此计数不包含其他应用的账户用量。相同原词、识别结果与调用参数可复用已校验缓存。额度不足且无备用服务、连接失败、截断或格式无效会让任务失败并保留旧稿。不会自动开通付费。未配置 Cloudflare 而已配置备用接口时，可以直接使用备用接口。

### 保存与验证

无法定位的内容记录在结果中，并在页面提示数量；无有效时间或未定位内容多于有效行时任务失败。取消、失败或服务重启不会覆盖旧时间轴。成功重新生成前保留旧稿到 lyrics/history；任务状态保存在 lyrics/jobs.json，重启后未完成任务标为中断，可重新生成。

生成流程测试：`node --test src/service/studio/lyrics-generation.test.ts`；分段与参考上下文测试：`python3 scripts/test-lyrics-worker.py`。播放器端到端测试同时覆盖按钮启动、排队、自动刷新和不打断当前播放。

2026-10-12 用《方向盘》V2 验证整段召回：原先误识别为“不凭了”的句子输出“铺平了”，没有续写窗口之后的下一句；尾段识别的四次重复保留。已更新本机程序并重新生成该版本，验证了播放器高亮、跳转和 LRC 下载，旧稿保存在历史目录。该版本仍有 4 处未定位，不代表整首识别无误。详见[整段召回回归](evidence/lyrics-passage-recall-2026-10-12.json)和[最初错字对照](evidence/lyrics-reference-context-2026-10-12.json)。

2026-10-21 修正参考段落检索的顺序问题：重复副歌中的相同句子可能让原先的无序字片段评分召回相反顺序的候选，从而遗漏两句之间的原词。现在按有序字片段召回连续原文，保留中间句；评分仅用于参考上下文检索，不直接替换歌词。截图对应版本的两处错句已按原词改为“野餐垫鼓起一面帆”，原有时间和三次演唱保留，旧稿已备份，接口及 LRC 已核验。

Qwen3.5-2B 的 ONNX 和 Ollama 独立单轮核对试验尚未通过，仍有错配、漏配和错误接受无关句子的情况，未接入正式自动写入。核对代码使用 TypeScript，不引入 Go Agent SDK；本地 ONNX/Ollama 保留为试验路径，正式流程使用上文配置的大模型。实测及限制见[验证记录](evidence/lyrics-reference-order-and-qwen35-2b-2026-10-21.json)。当前自动结果仍是需要试听核对的草稿。

Cloudflare 选型试验中，同一批 13 项基础用例的单轮通过数为：Qwen3-30B-A3B 3 项，Qwen3.8-27B 11 项，GPT-OSS-120B 9 项，Nemotron-3-120B-A12B 8 项。另测了整段无关句与半句两个控制用例；这是一首歌的窄样本，不是通用准确率。27B 未通过项包含一个误配负例和一个输出截断，不能都归为模型理解错误。

早期两轮试验保留原始对话，由模型复查初稿，不提供测试答案。27B 已完成的 8 项复查通过，复杂副歌请求超时；GPT-OSS 的 9 个整段及控制用例仍为 4 项通过；Nemotron 在三个重点单句中修正了无关句误配，却把两个正确改词改成无法对应。完整响应见[选型试验记录](evidence/lyrics-cloudflare-model-trials-2026-10-21.json)。用户选定 27B 后，正式接入改用连续候选段落、JSON 输出和非思考模式限制回复长度；两轮分歧保留识别原文，失败保留旧稿，不把复查结论直接当作事实。接入验证见[27B 接入记录](evidence/lyrics-qwen38-integration-2026-10-21.json)。

试验输入、评分与 REST 调用位于 `scripts/experiments/cloudflare-lyrics-review.ts`；两轮复查位于相邻的 `cloudflare-lyrics-review-agent.ts`，回归测试为 `node --test scripts/experiments/cloudflare-lyrics-review.test.ts`。默认仅展示请求数量；实际调用须显式添加 `--run`。凭据从本机环境或 `--env-file` 读取，不保存到仓库；新增的付费候选尚未调用，没有升级套餐或充值。
