# 基于音乐版本改谱

在已完成的音乐版本中，点击「修改这版」右侧的展开按钮，选择「转为器乐演奏」或「修改乐谱」。直接点击「修改这版」仍然修改创作要求。

## 两个入口

| 入口 | 操作 | 保留与变化 |
| --- | --- | --- |
| 转为器乐演奏 | 把原谱人声声部的主旋律转到器乐声部 | 新版固定使用纯音乐设置、器乐适配器及无歌词段落标签；重叠音符默认提示冲突，用户也可明确选择主旋律优先 |
| 修改乐谱：只改和弦 | 复制或下载要求与原谱，交给任意 AI / LLM；粘贴或导入返回的完整 ABC | 检查两个声部的音高、起音、时值、速度、拍号、调号和段落均未改变 |
| 修改乐谱：只改速度 | 输入 20–300 BPM | 只修改谱的速度；再由音乐模型生成新音频 |
| 修改乐谱：段落 | 选择明确标注的段落，重复或删除 | 同步处理对应歌词；段落边界或歌词无法对应时拒绝操作并说明原因 |

AI 改谱不要求安装特定应用，也没有内置 AI 对话或自动调用。纯文本材料可用于任何能处理 ABC 的 AI / LLM。输入材料由用户自行交给所选服务。

## 使用顺序

1. 选择来源版本，打开上述入口。系统直接读取该版实际保存的 ABC。
2. 填写修改内容与新版创作要求，点击「检查并保存草稿」。此时不生成音频、不增加音乐版本。
3. 对比原谱和新版草稿。简易试听只播放旋律音符，不播放和弦伴奏；它不代表模型生成的音色。最多试听前 120 秒。
4. 点击「生成新版本」。新版保存在同一声音下，记录来源版本与修改类型，进入现有生成队列。
5. 在版本列表中试听比较、下载或选为成品。原版及原有成品选择不变。

已检查的草稿保存在工作目录 `music-edits/` 中。未检查的输入保存在当前浏览器。关闭窗口后，从同一版本、同一修改范围重新进入即可恢复。修改内容后必须重新检查；同一份已检查草稿重复提交只返回同一音乐版本。需要再生成一次时，重新检查并保存草稿，形成新的草稿修订。

## 支持边界

- 需要已完成、未删除、有真实 ABC 文件的 YuE2 音乐版本。导入音频、音频调速版或未保存 ABC 的历史版本不能直接改谱。
- 历史版本若缺少明确的纯音乐／演唱设置或创作要求，会提示先用「修改这版」明确设置并生成新版本，不猜测用户意图。
- 段落操作需要原谱中明确的段落标记；暂不支持跨段落延音和中途变调、变拍的复制删除。
- 乐谱检查验证结构与保留约束，不能保证生成音频逐音符复现。纯音乐以正确的生成参数为准，不附加人声识别或人工审核门槛。
- 彻底删除来源版本时，清除该版的改谱草稿；已有子版本独立保留。

## 实现与验证入口

正式工作台与独立试用页共用 `public/yue2-score/` 的 ABC 处理工具。正式页面不依赖 4321。工具及上游 Apache-2.0 许可证随二进制打包，运行时优先使用已安装音乐环境的 Python，不加载模型权重。

- 业务与持久化：`src/service/studio/music-edits.ts`；生成复用 `StudioService` 与 YuE2 队列。
- 界面：`src/workbench/studio/music-edits.ts`。
- 回归：`src/service/studio/music-edits.test.ts`、`scripts/verify-music-edits-ui.test.mjs`、`scripts/verify-music-edits-binary.mjs`。
- 原独立页面保留用于试用，见 [试用页说明](../src/trials/yue2/README.md)。
