正式入口、使用范围和 MCP 调用见[音效生成](../sound-effects.md)。本次将固定版 Stable Audio 3 Small-SFX 接入共享资源队列；声音库与 MCP 使用同一任务和保存路径。音效以独立 WAV 保存，记录原始描述、时长与种子。模型环境位于工作目录外，作品备份只含记录和已生成音频。

## 真实模型

Apple M4 / 32 GiB，隔离工作区；固定上游程序 commit `790793b89ddceea612be9ce42ff6830d18f6fa57`、权重 revision `30cb2644da54bfa63275d1bc7f1fa67fc718680f`、MLX 0.32.3。真实 MCP 调用准备模型并串行生成 3 秒咕噜声与 5 秒碎纸机，检查非静音、时长、WAV 下载、输入与来源，重启后两条结果可用；实际取消排队和运行中的任务并确认所属进程退出；备份与恢复后记录和音频可用。使用预先下载的官方文件副本，安装过程仍重新校验固定 SHA-256；不是一次全新网络下载验收。

最后一次成功运行中，3 秒样本模型进程生命周期峰值 1,718,699,952 字节、资源队列采样峰值 1,480,790,624 字节；5 秒样本分别为 1,746,487,168 和 1,477,300,424 字节。两种计量不同，采样不代表瞬时峰值。以上仅说明这两次输入；模型效果与接点听感仍待人工试听，不代表所有声音均达标。执行证据和 WAV 位于忽略目录 `test-results/sound-effects-integration-2026-11-08/real/`。

一次真实复验因系统内存压力偏高而在安装准入阶段等待后失败，未启动模型；保留 `real-second.log`。压力恢复后按原规则执行并通过，未改阈值或自动重试。

## 故障与回归

- 新功能先记录缺少模块、资源档案与 MCP 工具的红灯，再分别通过服务、资源和 MCP 用例。还验证准备取消、排队/运行中取消、超出 5 GB 拒绝、文件变更、保存后重启恢复以及声音库分类。
- 新增按钮导致 720 px 宽窗口横向溢出；保留首次完整回归日志 `verify-all.log` 和截图，修正布局后原尺寸播放列表用例通过，未修改门槛。
- 复现后台音效失败后重新打开窗口不显示原因；修复后用浏览器回归验证。
- 复现从音色创建旁白时项目或声音提交成功但响应丢失导致重复；首次创作和普通新建也有相同风险。现在三条入口均使用固定身份恢复已创建项目和声音；同时验证重启、并发重试、不同输入冲突、声音索引写入失败后的恢复及关闭窗口后的迟到响应。首次红灯、一次将冲突状态误断言为 400（实际为 409）的测试失败、复验日志均保留。
- 一次完整回归期间又修改并重建了代码，故中止并保留 `verify-all-final.log`；另一次运行中发现其他新建入口有相同响应丢失问题，主动中止并保留 `verify-all-clean.log`。这两次均不计为通过。
