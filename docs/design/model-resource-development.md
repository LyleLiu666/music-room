# 模型资源管理开发记录

目标与轮次：[设计](model-resource-management.md)、[开发计划](model-resource-management-plan.md)。此页记录开发事实，不能代替最终验收。

## 第一轮：入口核对与调度核心

已完成。本轮提交以 `feat(resources): add hardware admission and serialized task coordinator` 标识。本轮交付核心契约、可注入硬件准入策略、统一有界 FIFO、取消与资源清理；实际业务引擎从第二轮接入。

核对了本机固定 YuE2 源码：`create_app` 的 lifespan 启动 Worker；Worker 管理内部执行，模型状态不应由外层 HTTP 启动状态推断。第三轮必须关闭历史排队自动运行旁路，并持有执行权直到真实任务结束。

### 契约与兼容决定

- 各业务服务继续保存任务、版本与产物；协调器只持有执行权、临时预约和有界诊断历史。
- 内存采用字节；统一内存只有一个池，独立显存逐池检查。未知/过期指标和未知需求不准入，不使用开发机容量推断。
- 完整任务峰值与已驻留资源分开处理；复用模型只预约增量，主服务其他占用仍扣除。
- 新资源子状态投影到旧业务 queued/running/failed/cancelled/interrupted，不扩大旧顶层枚举造成历史解析失败；原因码独立保留。
- YuE2 的用户可见任务 ID 继续采用 32 位十六进制，本地生成稳定 ID 并保存上游 ID；历史 ID 原样保留。未发给上游也要可查询/取消，音频读取不能启动模型。
- 独立显存/其他平台只验证策略契约，未适配后端不得放行；数值策略由第六轮标定，本轮仅使用显式注入的测试参数。

### TDD、review 与验证

- 基线：服务 133 项、普通 28 项测试通过，构建通过。
- 预算策略六组行为测试先在“全部放行”的最小契约上失败，再实现容量、动态可用量、逐池限制、可信度与驻留扣减。
- 调度测试覆盖三引擎竞争、先卸载后切换、probe 期间取消、卸载失败封锁、容量拒绝、超时、队列上限、状态保存失败和空闲释放。
- Review 发现并以失败测试复现：排队取消等前任务完成、重复 close 提前返回；已修复。补充驻留查询异常封锁、关闭时尽可能清理所有适配器、空闲释放后的状态复核。

## 第二轮：跨工作区互斥、所属进程与语音/转换接入

本轮提交以 `feat(resources): supervise owned model groups and unify speech conversion queue` 标识。

- 同用户的全局租约登记服务、监管进程和模型进程身份；复核启动时间，拒绝损坏/符号链接租约，不按名称杀进程。监管进程组仍有活跃后代时不得恢复租约。
- 模型进程继承已经登记的监管进程组，消除“模型先启动、登记前监管进程退出”的孤儿窗口。取消由 stdin 关闭、TERM、超时组 KILL 逐级处理；进程实际退出后才交还执行权。
- MusicService 创建唯一协调器，TTS、转换和参考清理进入同一 FIFO。新语音不再因转换正在运行而被拒绝；已有排队语音顺序保留。
- 原生 TTS 增加可重复的卸载与驻留查询。当前用户级租约策略在每次重型任务结束后卸载，优先保证释放和跨工作区交接；驻留复用仅在无用户级租约的显式测试夹具中验证。
- 任务等待时不标为正在推理；取消完成前保留非终态，避免删除保护提前失效。关闭服务先停止准入，并并行取消各业务服务，再等清理完成。
- 生产协调器在第六轮补齐平台探测与已测模型档案前，不因缺少指标或需求而放行。测试采用显式注入的假硬件/需求，没有环境变量式生产旁路。

### Review 与修复

- 新排队行为先在旧“两两忙碌拒绝”实现上失败，再接入共同队列。
- 修复协调器关闭信号未传到业务 driver、多个已登记语音任务下准备环境的忙碌判断、任务取消提前进入可删除终态、监管父进程退出但模型后代仍活着的恢复漏洞。
- 修复真实进程夹具读取刚创建但尚未写完的 PID 文件的竞态，改用进程消息确认。
- 首次全量检查出现一次 stdio 连接中断，单项复测通过；构建与依赖 dist 的检查改为顺序执行。最后全量结果以本轮提交前日志为准，不隐藏初次失败。

### 验证范围

- 19 项进程/原生夹具/交叉调度专项测试通过，包含真实孤儿进程组及原生服务夹具的退出确认；这些不是新模型推理的证据。
- 服务/页面检查 20 项通过；TypeScript、构建通过。
- 完整服务回归 158 项通过，结果记录于 `/tmp/music-resources-r2-reviewed-tests.log`；页面日志 `/tmp/music-resources-r2-service-ui.log`，构建日志 `/tmp/music-resources-r2-build.log`。
- YuE2 生成/启动接管属于第三轮，安装互斥与完整动态监控分别在第五、六轮完成；当前中间提交不能宣称完整资源保护交付。

## 第三轮：音乐代理与按需启动

- MusicService 中的 YuE2 生成先保存本地稳定任务 ID，再进入同一队列；上游只接收当前获准的一项任务。POST 丢失响应不自动重试，避免重复推理。
- 准备/启用只表示环境及模型文件可用；旧 autoStart 不再在打开工作台时加载模型。停止操作取消工作台音乐任务；资源卸载保留启用配置。
- 任务保存上游 ID、输入、所属安装目录和音频校验值。历史通过专用 Python 的只读 SQLite 查询读取，不导入 MLX/模型；音频读取与删除使用所属目录、路径检查和 ID 映射。
- 固定上游启动脚本在 lifespan 开始前将旧 queued 任务标为中断；变更请求必须持有内部执行凭据。模型进程接入已登记的监管进程组，预算向上游传递。
- Review 修复预先公布 done 但音频尚未校验/进程未释放、正常停止被误认为意外退出、初次未安装时历史迁移被永久缓存等问题。任务记录校验绝对目录，防止损坏路径引起目录遍历循环。
- 新增三项先失败再通过的代理测试：延迟启动/串行/卸载后读音频、排队取消不启动、旧本地和上游任务中断而不恢复执行。保持独立引擎旧接口测试；工作台接入使用新行为。
- 服务回归 161 项、TypeScript、构建通过。服务与页面验证结果见本轮验证日志。历史迁移不删除原数据库与作品；真实模型峰值仍由第六轮测量。

## 第四轮：渲染、调速与播放器缓冲区

- 乐谱渲染的全部排队任务接入统一队列；渲染进程在写入任务前登记租约，取消等待进程退出，保存产物期间继续持有执行权。
- 调速的等待和计算移出 Studio 的业务锁。API 保持原有完成后返回语义；计算在独立、可取消的子进程中运行，后台资源状态可查询，通过来源版本取消或后续资源接口取消。处理中保护来源版本/声音/项目；相同请求共用一次计算。
- 解码前读取 WAV/FLAC 头部长度，约束时长、采样率、声道并估算压缩输入、PCM、中间数组及输出副本；计算循环检查取消。编曲的全段缓冲区、调速输入/解码/输出需求由第六轮接入生产估算。
- 音乐历史校验使用流式 SHA，不为每首历史音频分配全文件缓冲区。播放器缓存按 64 MiB/六项淘汰未使用 URL，保留正在播放/当前刚加载的音频；因此它不是浏览器进程总内存的硬上限。
- Review 修复重复调速请求登记竞态、Studio 事务克隆内部 Promise 导致挂起、处理时删除来源、子进程在输入登记失败时继续运行等问题。输入校验失败不发布半成品，旧调速文件与编号保持兼容。
- 专项 15 项与新增并发调速测试通过，最终完整服务 164 项、TypeScript、构建通过，真实浏览器调速用例通过。模型 driver 仍为测试夹具，独立 DSP 子进程实际执行。日志 `/tmp/music-resources-r4-final-tests.log`、`/tmp/music-resources-r4-speed-ui.log`。

## 第五轮：安装、下载与磁盘预算

- 语音准备、音乐准备及现有转换 CLI 导入共用 installation 执行权；排队时不下载。首次安装依据现有发行文件/依赖的保守磁盘预约，已经准备好的环境不再次要求完整安装空间。
- 检查目标文件系统可用空间，保留 2 GiB；下载开始与每 64 MiB 流写复核空间。指标无效、空间不足明确拒绝。语音程序下载改为流式校验/写盘；原生权重保留范围续传与 SHA 校验，YuE2 保留已完成权重、清除上游不能恢复的随机暂存文件。
- 解压等固定命令也改为 stdin 监管进程，先登记监管组再执行命令；退出/取消停止整组，等待退出后释放执行权。独立二进制增加同一个 command-worker 入口。
- 参考清理的首次依赖准备仍在清理任务执行权内，不另开旁路，开始前检查相应磁盘预算。转换继续使用现有固定权重本地导入，不添加未验证的自动下载供应源。
- 新测试验证目标磁盘不足/指标损坏、推理与安装互斥、语音安装等待取消不调用 driver。安装子进程、断续下载及损坏模型的既有测试全部保留。
- Review 修复 macOS 标准目录 `/var` 映射造成磁盘路径误拒绝；以实际文件系统的规范路径检查。取消贯穿导入校验和复制步骤，最终安装标记最后写入。
- 完整服务回归 166 项通过；补充业务安装用例后专项三项通过，TypeScript、构建通过。第五轮生产安装的动态内存准入继续由第六轮补齐，磁盘数字是安装余量策略，不是推理内存实测。

## 第六轮：实际探测、运行保护与固定需求档案

- macOS Apple Silicon 读取实际物理容量、共享内存可用估计、系统压力、交换占用与进程组 physical footprint。统一内存只有一个池；不把 RSS、Metal 分配或交换空间重复相加。任务占用含主服务相对准入时的增量。
- 每个任务重新准入，运行期间约每秒采样；超预约、危险压力、交换占用相对任务开始增加 512 MiB 或指标失联时停止所属任务，等退出确认再交还执行权。采样保护不是瞬时硬上限。
- 档案绑定固定程序、模型和依赖身份；升级后身份不匹配即未验证。语音正文最多 140 字；参考清理 0.3–15 秒；音乐风格最多 1000 字、歌词最多 2000 字。更长输入不以既有测量外推放行。
- 语音 6 GiB、参考清理 8 GiB、转换 10 GiB、音乐 14 GiB 是保守任务预约，包含加载和后处理，不能当作本次采样峰值。音乐预算同时传给 MLX；没有按本机 32 GiB 固定应用总额。安装与有界媒体处理另有需求规则。
- 默认整机保留 max(30%, 2 GiB)，另保留当前可用量中的 1 GiB。8 / 16 / 24 / 32 / 64 GiB 和独立显存通过模拟策略验证；只有本机 M4 / 32 GiB 执行真实模型。16 GiB 并不承诺音乐可运行，8 GiB 不能获准当前原生语音。
- 参考清理初测触发超额保护，CoreML 路径在 6 GiB guard 下采样到约 6.8 GiB，任务停止并保留原音。改为 CPU 执行同一固定分离/降噪/去混响流水线，短参考完成；这不替代用户的音质试听。
- 实测在隔离目录克隆已有安装、顺序取得用户级租约，不改原用户作品和原引擎。两个音乐档位完成后释放，另一工作区的长参考任务才获得执行权。紧凑证据见 [实测档案](model-resource-evidence.json)，原始产物位于本机 test-results/resources-real。

### Review 与验证

- Review 修复把未来程序身份自动当成已验证档案、保护性失败被显示成用户取消、准备阶段提前锁住音乐目录、轮询重复写盘。参考清理在账本中单独标为 reference。
- 以失败用例复现“语音在卸载确认前标成功”；完成状态改为在资源结算后发布，转换和参考清理一并校正。清理失败不能公布成功产物。
- 完整服务回归 180 项、TypeScript、构建通过；监控专项覆盖超额、危险压力、指标缺失及采样异常、交换增长。第五轮最后含追加用例的实际全量为 167 项，修正前页的 166 项统计。
- 真实记录并非不同容量真机证明，也没有覆盖任意输入。音乐/参考标定运行尚未采集 swap 增量；交换保护通过契约测试，后续二进制实际验收继续观察。

真实采样结果：语音 4.32 GiB、短参考 CPU 清理 5.61 GiB、长参考 7.21 GiB、转换 2.57 GiB、快速器乐 5.74 GiB、质量人声 5.44 GiB；两档音乐分别生成 240 / 50 秒，均完成并在释放模型后仍能读取音频。长参考与音乐跨工作区顺序执行，结束无驻留。
