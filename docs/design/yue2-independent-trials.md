# YuE2 新能力独立试用设计

当前调整：按用户要求移除 01 独立写谱页面，保留 02 主旋律转器乐与 03 约束改谱。已有试用数据保留，ABC 导入与查看/试听/下载/按谱生成功能放在保留页面中；旧 `/plan` 地址跳转到 `/transfer`。下文三页方案及验证为此前阶段记录。

当前实现：转器乐与约束改谱已按用户确认接入正式音乐版本菜单，详见 [基于音乐版本改谱](../music-editing.md)。以下保留独立试用阶段的设计依据；旧的“尚未接入”描述仅指当时阶段。

原提案日期：2026-10-17。状态：历史设计，当前功能以使用说明为准。

本文是 YuE2 新能力试用的范围与接入决策依据。正式流程仍以[声音创作空间](studio.md)和[YuE2 使用说明](../yue2.md)为准。本文中的“首批”是建议的开发顺序，不表示用户已经验收或批准正式接入。

## 1. 结论与范围

用户对当前功能总体满意。新增能力必须先作为独立功能试用，由用户确认效果和操作方式后，再逐项接入现有流程。试用通过一项，不代表其他项目也获准接入。

**建议首批做三个功能，按顺序交付；每项做完即可独立试用：**

| 编号 | 独立试用功能 | 用户可以做什么 | 确认后拟接入的位置 |
| --- | --- | --- | --- |
| T1 | 先写谱，再生成音乐 | 看清作品的旋律、和弦和结构；同一份谱反复生成不同演绎 | 音乐创作表单的可选入口，保留现在的一键生成 |
| T2 | 把旋律改为器乐演奏 | 将模型生成或已有 ABC 中的人声旋律交给乐器演奏 | 纯音乐创作的可选生成方式，以及版本菜单的“改为器乐演奏” |
| T3 | 按要求改谱，对比试听 | 用自然语言要求修改和弦、速度或段落，检查哪些地方变化，再生成新版本 | 音乐版本的“修改这版”，保留现有编辑方式 |

三项共享乐谱读取、版本保存和试听比较能力，但不建设通用插件系统或完整数字音频工作站。T1 是公共基础；T2、T3 各有独立页面和试用记录，不强迫用户走完全部步骤。

### 1.1 已确定的要求

- 本轮只产出设计文档。后续开发不替换正式生成链路、不迁移已有作品、不改变当前默认参数。
- 试用结果独立保存，不自动进入正式项目、版本列表、声音库或成品列表。
- 用户决定是否好用、是否值得接入；不能用开发测试通过替代用户试用结论。
- 纯音乐的项目验收边界是输入与调用正确。参数和曲谱条件正确，而音频仍有人声，记录为模型效果问题，不增加强制人声检测、人工确认或下载拦截。
- “用户确认试用功能可以接入”是一次功能级决策，不是要求每首音乐都进行人工审核。

### 1.2 候选功能取舍

| 候选 | 判断 | 理由与进入条件 |
| --- | --- | --- |
| 分阶段写谱、按谱生成 | 首批 T1 | 已有 ABC 读写基础，可让乐谱成为可复用作品，而非高级文本框 |
| 人声旋律转器乐 | 首批 T2 | 官方提供了明确的谱面转换路径，值得与现有器乐适配器路线做独立对照 |
| 受约束的对话改谱 | 首批 T3 | 支持有依据地修改已有作品；谱面约束可验证 |
| 同谱换风格、少量变体、A/B 试听 | 纳入 T1–T3 的共用操作 | 用于理解修改效果，不单独开一套功能；首版每次只提交一个音频任务 |
| 原曲翻唱、跨风格改编 | 后备候选 C1 | 依赖转谱；必须先取得新的转谱效果证据，不能默认恢复此前暂停方向 |
| 哼唱续写 | 后备候选 C2 | 输入较简单，值得小样验证，但仍依赖转谱；在 C1 的前置验证后再决定是否开发 |
| YuE2 内部声音克隆 | 暂不安排 | 当前锁定运行版本未确认可用接口；现有音色转换已经承担换声任务 |
| 特殊唱法、多语言技巧 | 作为生成样例探索 | 不据宣传描述新增按钮，也不承诺“完美”实现 |
| 局部音频无损替换、完整分轨工程 | 不纳入 | 当前乐谱修改会重新生成录音，不能承诺其他位置波形不变；ABC 不等于全部乐器分轨 |

“值得做”的排序是基于当前用户要求和工程现状的建议，没有额外用户访谈依据。

### 2.2 已核实与待验证事项

官方 Python 接口提供分阶段生成，已有乐谱可作为固定输入；编辑后的谱应作为新输入，不能沿用旧计划中不匹配的 token 前缀。[官方生成说明](https://github.com/multimodal-art-projection/YuE/blob/main/docs/generation.md)

当前产品使用社区 YuE2 Studio + MLX，不能直接把官方 CUDA 示例当成本机可运行方案。此次只读检查确认：本机锁定的 Studio `engine.py` 内部已经顺序调用规划、语义生成、声音合成、解码；安装的 `lyra.pipeline` 有对应方法。但当前产品没有“只写谱”接口，分阶段保存、重载和独立资源释放还未实测。

本轮核查版本：Studio `f696147a985081848d4b0310cbe9b10b16259be6`，MLX 分支 `1332b148bf5588c357a14323a03c9b9e9f2b2737`。实现前应重新核对实际安装版本，记录差异，不直接升级正式环境。

**开发前置验证：** 在独立进程和输出目录中，证明“只规划即可退出”和“固定 ABC 可再次生成”可行；验证取消、模型释放和实际输入记录。失败时修正试用实现或缩小范围，不通过生成整首后丢弃音频伪装成“只写谱”。

## 3. 三个功能的试用设计

### 3.1 T1：先写谱，再生成音乐

**用途：** 先确定作品内容，再投入较长的音频生成时间；同一份旋律可以有多个演绎版本。

**操作流程：**

1. 打开独立试用地址，选择“先写谱”。填写音乐描述、作品形式；演唱模式填写歌词。
2. 点击“生成乐谱”。任务只完成规划，成功后释放模型资源，不自动继续生成音频。
3. 查看乐谱摘要和谱面：速度、拍号、和弦、人声/器乐声部、可识别的段落。缺少段落标记时显示“未标注”，不编造主歌、副歌。
4. 可用简单合成音试听谱面旋律，明确标为“乐谱试听”，不代表 YuE2 的音色、编曲或最终效果；支持不了的谱面构造明确报错，不静默删音。
5. 点击“按这份谱生成”，提交固定 ABC。修改风格或种子可再生成一版；原谱、原音频保留，可并排试听。

**首版范围：** 支持模型写谱、导入本机 ABC，以及从用户指定的正式作品读取乐谱副本。不做音频转谱、钢琴卷帘编辑器或全功能制谱软件。

**交付物：** 原始请求、原始乐谱、摘要、生成时实际使用的谱、音频与版本关系。高级详情可查看 ABC；用户不必先学习 ABC 才能试用。

**验收：** 只写谱不产生音频任务；固定谱输入不被重新作曲替换；重开试用页面可继续；生成新音频不覆盖旧内容；乐谱试听和真实生成的区别清楚。

### 3.2 T2：把旋律改为器乐演奏

**用途：** 将喜欢的旋律转为钢琴、吉他等器乐演绎，验证谱面处理是否比当前纯音乐调用方式更适合用户。

**操作流程：**

1. 选择 T1 乐谱或导入 ABC，也可输入描述让 YuE2 先写谱。
2. 描述期望的乐器与风格，点击“转为器乐谱”。
3. 页面展示原谱/转换谱，以及音符保留、重叠处理和不支持结构的说明。
4. 点击“生成器乐版本”，提交转换后的固定 ABC 与纯音乐输入。用户直接试听、下载，无额外验收关卡。

官方提供的器乐工作流会将人声旋律转到器乐声部，并记录重叠处理；这是待验证的新路线，不证明当前适配器路线本身无效。[官方器乐流程概述](https://github.com/multimodal-art-projection/YuE#agent-skill)

**谱面转换规则：**

- 按音符事件转换，不通过替换 `Vocal`/`Ins` 字符串冒充改谱。
- 保留原人声旋律的音高、起音和时值；人声声部只保留休止及需要的和声信息。
- 保留不重叠的原器乐旋律。存在重叠时，首版停止转换并说明位置；用户可以明确选择“以主旋律为准处理重叠”，之后必须记录被缩短或移除的器乐音符。
- 拍号、速度、变音、连音和保留的和弦时刻必须可验证。不支持的 ABC 构造不能静默丢弃。
- 转换后的谱必须作为新请求；歌词字段只有协议式段落标签，不能携带旧演唱歌词；模型与适配器配置完整留档。

**验收分两层：** 工程测试验证谱面与实际提交内容一致；用户听评决定这条路线是否值得接入。谱面正确但音频出现人声，记录模型表现，不引入自动音频拦截。

**对照方法：** 同一描述、同一原始谱和已记录配置下保留原路线与新路线结果。若适配器、采样设置不同，显式列出，不能把全部差异都归因于转谱。至少覆盖用户此前的梦幻电子配乐，以及钢琴、吉他旋律；每类至少两个固定种子，不只保留最好的一次。

### 3.3 T3：按要求改谱，对比试听

**用途：** 基于已有作品做有边界的修改，避免只有“改提示词再抽一次”的方式。

**首版三个可试用操作：**

| 操作 | 允许变化 | 必须保持 |
| --- | --- | --- |
| 只改和弦，例如更温暖或偏爵士 | 和弦符号及对应和声安排 | 旋律音高、起音、时值、速度、段落顺序、歌词 |
| 只改速度 | 速度标记 | 音高、以拍为单位的音符位置和长度、段落及歌词顺序 |
| 重复或删除明确段落 | 指定段落及其对应歌词 | 其他段落的音符和内容；无可靠段落边界时先请用户明确范围 |

**交互与 Agent 边界：**

1. 选择原谱副本，输入自然语言修改要求。
2. 首版通过用户选择的 AI / LLM 对话完成语义理解与改谱：页面提供包含版本标识、原谱位置和约束的任务材料；用户明确交给 AI / LLM 执行。
3. AI / LLM 通过试用接口提交修改提案，页面展示“改了什么”“哪些保持不变”及检查结果。仅复制材料不表示任务已经开始，页面不得显示“AI 正在修改”。
4. 用户查看提案后点击“生成修改版”，对比原版和新音频。不满意时从任一谱面版本再改，保留分支来源。

这是“独立页面 + 任意 AI / LLM”的试用方式，不冒充已经内置一个聊天模型。是否在页面内直接对话，以及使用哪种模型服务，留到用户确认 T3 有价值后另行设计。

LLM 根据完整要求理解修改意图；固定按钮只作为用户明确的操作协议。不得用关键词匹配将自然语言偷偷分流到改和弦、改速度等操作。确定性谱面检查负责验证音符和约束，不替代语义理解。

**失败行为：** 谱面解析失败、约束检查失败或原谱版本已变化时，保留提案和原因，不提交音频生成；不悄悄扩大修改范围。未明确要求重新作曲时，不让 Agent 替换整首旋律。

**能力边界：** 改谱后生成的是新的完整录音，不保证未修改位置波形一致；固定种子也不是旋律锁。[官方编辑说明](https://github.com/multimodal-art-projection/YuE/blob/main/docs/editing.md)

## 4. 独立试用的工程隔离

### 4.1 入口与数据

- 首版使用单独本机试用服务和 URL，不把实验按钮直接放入当前正式创作表单。开发交付时提供可点击入口及最短操作说明。
- 试用文件拟存于工作目录下 `experiments/yue2/`，使用独立索引和任务记录；正式 `studio.json`、项目版本、成品标记不写入。
- 读取正式作品时，通过现有只读接口取得用户指定版本的副本，记录来源和校验值；后续编辑只作用于副本。正式来源删除后，已保存试用副本仍可独立使用。
- 试用期间可下载音频、ABC 和试用包；不提供暗中写回正式项目的捷径。通过验收后的接入版本再提供显式“保存为新版本”。

### 4.2 模型与资源

- 沿用当前硬件准入和跨工作区执行租约。独立服务不等于可以同时抢占模型内存；正式任务与试用任务协调排队。
- 模型权重可只读复用；试用任务、日志、缓存及临时文件归试用目录。不能把实验补丁直接写入正式引擎源码、共享数据库或安装记录。
- 优先在隔离的试用适配层调用锁定 MLX 运行时。若依赖版本必须变化，使用独立环境，记录版本差异；不升级或重建正在使用的正式模型目录。
- 打开页面、读谱、查看对比不加载音乐模型；规划和音频生成分别提交任务，等待用户操作期间不保留模型占用。
- 需要新模型或依赖时列出用途、存储需求和安装位置，显式启动安装；不在试用页面后台下载。

### 4.3 最小对象与边界

| 对象 | 保存内容 | 关键约束 |
| --- | --- | --- |
| 试用项目 | 名称、功能编号、创建时间 | 不复用正式项目 ID |
| 乐谱版本 | 来源、父版本、原文、解析事件、校验值、变更与约束结果 | 新版本不可覆盖旧版本；解析器版本留档 |
| 生成尝试 | 绑定的乐谱版本、实际请求、种子、模型/适配器身份、任务状态、音频与校验值 | 重试创建独立尝试；不能混用另一版本的请求或音频 |
| 试用反馈 | 用户所评版本、喜欢/不喜欢、具体问题、是否同意接入 | 反馈与技术检查分开保存 |

建议将试用代码围绕“乐谱规划、器乐转换、受约束修改、生成尝试”组织。解析规则、转换逻辑及其测试放近；仅在多个功能实际共用且语义一致时抽取公共能力。

试用接口至少覆盖：创建规划任务、导入乐谱副本、读取/比较乐谱、器乐转换、提交修改提案、按固定谱生成、查询/取消任务、读取产物。接口必须携带明确的乐谱版本与校验值，不能依赖“当前选中项”或模糊文件名。具体 API 字段在功能开工时随测试落实，不在本提案中冻结现有正式接口。

## 5. 验证与试用通过标准

### 5.1 开发顺序：先写失败用例，再实现，再交付试用

| 范围 | 必须覆盖的验证 |
| --- | --- |
| 规划 | 只运行规划阶段；计划可重读；取消及重启中断不会偷偷续跑音频生成 |
| ABC | 正常谱、空谱、不支持构造、变音、连音、变拍；失败时保留输入，明确原因 |
| 器乐转换 | Vocal 有音符/无音符、Ins 独立前奏、两轨重叠、和弦变化；逐事件检查保留关系 |
| 改谱 | 只改和弦却改了旋律必须失败；速度修改不应误改拍位置；段落修改同步处理歌词 |
| 语义理解 | 同义表达、否定要求、复合要求和指代不明；以完整意图判断，不使用词表路由 |
| 请求 | 固定谱与实际提交内容一致；纯音乐无歌词正文；两档生成配置不丢失作品形式 |
| 隔离 | 正式数据库和源音频校验值不变；共享资源不并发超额；退出试用不影响正式任务 |
| 页面 | 能完成完整操作、试听比较、下载、重开继续；有明确的等待/失败/取消状态，无虚假完成 |

工程通过不自动触发正式接入。开发者交付真实可运行入口、测试结果、全部对照音频和已知问题，用户实际试用后决定。

### 5.2 每项的用户试用任务

- **T1：** 用自己的描述先写谱，生成第一版；沿用同谱改一次风格，比较两版；关闭页面后回来继续。
- **T2：** 将一份旋律分别生成钢琴和吉他器乐，查看转谱保留说明；再试此前出现人声的梦幻电子描述。听感记录与输入正确性分别汇报。
- **T3：** 对同一作品分别尝试只改和弦、只改速度、重复一段；用户判断修改是否易懂、是否比当前方式更有用。

每项反馈结论只采用：**可以接入、继续独立改进、暂不做**。不设未经用户认可的满意度分数，也不以自动检测音频是否有人声作为纯音乐成功门槛。

## 6. 接入现有流程的条件与方式

| 阶段 | 交付 | 是否改动正式流程 |
| --- | --- | --- |
| A：本次设计 | 三项范围、候选取舍、独立方式与验收标准 | 否 |
| B：基础验证与 T1 | 可独立使用的先写谱/按谱生成 | 否 |
| C：T2 | 可独立使用的器乐转换与对照 | 否 |
| D：T3 | 任意 AI / LLM 协作的改谱与试听 | 否 |
| E：逐项接入 | 用户明确确认的功能，作为正式可选入口 | 仅接入已确认项 |

接入前需同时满足：本机真实路径已跑通、相关工程测试通过、独立试用问题已记录、用户明确确认该项值得进入主流程。之后按下列方式接入：

- T1 增加“先写谱”选项；当前一键生成继续可用。
- T2 增加“器乐改编”可选入口；是否替换现有纯音乐默认路径单独由用户决定。
- T3 增加基于所选版本的改谱入口；通过检查的改动生成新版本，原版和原成品保留。
- 试用结果如需进入正式项目，显式选择目标项目和声音，复制为新版本并保留来源；重复提交不得重复导入。
- 接入可按功能关闭入口；关闭不删除已经保存的作品，不要求回滚历史音频。

## 7. 暂缓方向与待商榷项

**C1 翻唱、C2 哼唱续写暂不承诺开发。** 上游提供相关链路不等于本机试用效果已经过关。先沿用此前转谱实验样本复测，再加入用户自己的目标素材；确认音高、节奏、时长和输出稳定性后，另写独立试用补充方案。没有新证据，不默认重启。

以下选择在试用过程中讨论，不阻塞当前文档交付：

- 简单乐谱试听是否足够有帮助，是否需要更复杂的谱面编辑。
- T2 的声部重叠处理是否需要更多音乐性选项；首版只提供严格拒绝和显式主旋律优先。
- T3 是否值得发展为页面内聊天；首版不引入额外模型服务和账户配置。
- 用户实际认可的样本、耗时与操作复杂度；未测量前不承诺节省多少时间或成功率。
