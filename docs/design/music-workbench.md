# Music Room 音乐工作台设计

状态：本轮范围已实现并完成开发验收；本文保留设计规则，后续事项仍按第 6 节处理。
日期：2026-10-08。
适用范围：现有纯前端 Music Room 的下一版交互与实现。
入口：[项目说明](../../README.md)；实现与验收记录：[开发记录](development-rounds.md)。

## 1. 设计结论

Music Room 下一版围绕 **选作品 → 听片段 → 比较版本 → 给出修改意见** 组织。继续使用 TypeScript、Web Audio、Vite 和本地音色，保留所有现有作品与导出文件。

从 MuseScore 借鉴三个原则：音乐内容占据工作区中心；选中的音乐片段决定试听范围；混音等详细工具按需展开。当前优先建设听评工作台，乐谱编辑和桌面软件接入另行验证。

本轮必须交付四项能力：

1. 歌曲与版本分层展示，同一首歌的版本归在一起。
2. 整曲概览与局部放大联动，能看清四至八小节中的旋律、和弦和留白。
3. 按小节选择片段并循环试听，支持现有的静音、独奏与音量调整。
4. 在同一首歌的可对应片段间切换 A/B 版本，减少反复寻找位置的操作。

第一版音乐必须原样保留。界面改造不修改任何版本的音符、编配或已交付音频。

## 2. 用户目标与现状

### 2.1 已确认的目标

用户希望让代码生成完整、可试听的音乐，工具尽量开源免费；作品库可以容纳多首歌和多个版本。音乐应有明确、好听的 riff，并通过回答句、配器和段落发展产生变化。修改结果需要可以反复试听和比较。

这些目标来自当前对话。本文没有其他用户访谈或可用性测试证据。“局部放大和 A/B 对比能提高听评效率”属于待实际使用验证的设计判断。

### 2.2 现有实现与缺口

| 范围 | 已有能力 | 本轮需要解决的问题 |
| --- | --- | --- |
| 作品组织 | 两个版本有独立 ID、乐谱和导出路径 | 当前平铺版本，没有独立的歌曲分组 |
| 播放 | 播放、暂停、跳转、音色加载与复用 | 没有片段循环 |
| 音乐展示 | 全曲段落和十一条音符轨道 | 三分钟压缩在同一视图，局部旋律难以辨认 |
| 混音 | 轨道静音、独奏、音量；主旋律三种音色 | 混音控制一直占据轨道左侧，缺少任务层次 |
| 版本切换 | 停止旧版，重置位置和混音 | 无法直接比较相同音乐位置 |
| 导出 | WAV 使用点击时的乐谱与混音快照；MIDI、JSON、成品独立 | 新增试听状态不能干扰原有导出语义 |

代码依据：[目录](../../src/catalog.ts)、[乐谱类型](../../src/music/score.ts)、[页面交互](../../src/main.ts)、[音频引擎](../../src/audio.ts)。

当前乐谱采用固定速度、4/4 拍与统一的十一种轨道标识。本轮沿用这些边界。不同作品可有不同固定速度、时长和段落；变拍与曲内变速需要后续扩展乐谱模型。

## 3. 页面与交互

### 3.1 信息布局

桌面布局示意：

```text
┌─────────────────────────────────────────────────────────────────┐
│ Music Room    雨巷来信 / 第二版       版本比较    混音    导出     │
├─────────────┬───────────────────────────────────────────────────┤
│ 作品库      │ 播放 / 暂停   时间、小节、拍   循环状态   总音量   │
│             ├───────────────────────────────────────────────────┤
│ 雨巷来信    │ 整曲概览：引子 → 主题 A → 过渡 → 副歌 → …         │
│  第一版     │             [当前查看范围]                        │
│  第二版 ●   ├───────────────────────────────────────────────────┤
│             │ 当前片段：第 9—12 小节     放大范围：4 / 8 小节    │
│ 其他歌曲    │ 和弦：…                                           │
│  …          │ 主旋律音符、休止与持续时间                         │
│             │ 伴奏轨道                                          │
│             │ [选择片段] [循环此片段] [清除选择]                 │
├─────────────┴───────────────────────────────────────────────────┤
│ 按需展开：混音器，或 A / B 版本与当前对应片段                     │
└─────────────────────────────────────────────────────────────────┘
```

歌曲、版本、当前片段与播放状态始终可见。收起混音器不会改变声音。频谱降为辅助信息，不占据主要工作面积。

窄屏采用单列：作品库进入可开关面板，播放控制保持可见；整曲概览、片段和混音依次排列。以小节起止选择器补足拖拽操作，页面本身不得横向溢出。

### 3.2 作品与版本

- 作品库按稳定的歌曲 ID 分组。标题相同不代表同一首歌；不靠标题或“V1”等文字推测归属。
- 每首歌显示版本数，展开后显示版本名和一句修改说明。当前作品应显示为“一首歌、两个版本”。
- 点击普通版本条目：停止旧版，从新版开头进入暂停状态，清除片段和循环，重置临时混音；总音量作为播放器设置保留。
- 保留 `#rain-letter-v1`、`#rain-letter-v2` 等已有直达地址。刷新只恢复版本，不自动播放。
- 无效地址回退到默认作品，并显示“未找到该版本，已打开默认作品”。浏览器前进、后退应切换到对应版本。
- 普通版本选择增加历史记录；初始化和无效地址纠正替换当前记录。A/B 临时切换不逐次写入历史，刷新返回进入比较前的版本。
- 本轮作品仍由代码目录注册。页面不增加上传、删除、在线生成或账号管理入口。

### 3.3 整曲概览与局部片段

整曲概览负责定位；局部视图负责看清音乐。二者使用同一份乐谱与播放位置。

- 点击段落跳到段首，同时将局部视图移至该位置，保持原来的播放或暂停状态。
- 局部视图默认显示四小节，可切换八小节；显示小节号、拍线与现有和弦标记。
- 音高轴在同一轨道的各个查看窗口中保持固定，避免缩放后误以为旋律改变。不同轨道默认分别显示，不把不同音域叠在一个图中。
- 播放位置离开窗口时按窗口翻页。用户手动查看其他位置后关闭跟随，提供明确的“跟随播放”开关恢复。
- 选区吸附整小节，至少一小节；起止小节可通过拖拽或输入控件设置。跨段落选区可以循环，但不参与本轮 A/B 比较。
- 反向拖选按较小小节号到较大小节号保存，单击选择一小节；拖拽越界限制在曲内。输入不存在的小节号时保留原选区并提示有效范围。曲尾不足四小节时仅显示实际剩余小节，不生成空白乐谱。
- 查看范围、选区、播放位置是不同状态：放大不会移动播放位置；选择片段不会自行发声；只有播放、跳转或循环操作改变听到的位置。

本轮图形用于查看和选择，不支持拖动音符改写乐谱。需要改变音高、节奏和编配时，由代码生成新的独立版本。

### 3.4 循环试听

点击“循环此片段”启用循环；无选区时该按钮不可用，并提示先选择小节。

| 操作 | 规定行为 |
| --- | --- |
| 暂停时启用循环 | 保持暂停；下一次播放从选区起点开始 |
| 播放时启用循环 | 从选区起点重新开始，随后反复播放 |
| 到达选区终点 | 准确回到选区起点，不播放终点之后的音符 |
| 循环中暂停、继续 | 暂停保留循环和位置；继续从暂停点播放 |
| 循环中修改选区 | 从新选区起点重新开始；暂停时仅更新选区 |
| 点击选区外的位置 | 关闭循环并跳转，显示“已退出片段循环” |
| 关闭循环 | 从当前位置继续整曲播放；暂停状态仍保持暂停 |
| 清除选择或普通切换版本 | 同时关闭循环 |

循环起点之前开始、但仍在持续的音符需要恢复。跨越循环终点的持续音在边界结束。边界使用短淡出、淡入抑制爆音，旧轮次的效果尾音不无限叠加；该方式用于片段检查，不承诺复现完整演奏进入片段前的所有混响历史。

### 3.5 A/B 版本比较

比较入口只列出当前歌曲的其他版本。A 与 B 明确显示版本名、修改说明和对应段落；普通切歌与比较切换使用不同入口。

**位置按“段落身份 + 段内第几小节、拍”对应。** 不用相同秒数、标题相似度或整曲进度百分比推断音乐对应关系。

本轮允许比较的条件：两个版本固定速度相同、均为 4/4；当前段落在目录中有明确的共同标识，且段落小节数一致。选区必须完整落在该段落内。当前两个版本应为引子、主题、过渡、副歌、间奏、再现、尾声配置明确对应关系。

没有选区时使用播放游标所在段落和段内位置；有选区时以选区所属段落为准，若游标在选区外则从选区起点进入比较。进入比较保持原来的播放或暂停状态。播放到下一段落时重新判断可对应条件，不满足则暂停并提示。

- A/B 切换保留段内音乐位置、选区与循环。正在播放则继续播放目标版本；已暂停则保持暂停。
- 默认比较两版各自原始混音，共用当前总音量。不自动做响度归一化；页面提示“比较原始混音，响度可能不同”。
- 进入比较时，如存在临时混音，显示“比较使用原始混音，退出后恢复试听设置”，并保存进入前的版本、位置、选区、循环、查看范围和混音快照。比较期间轨道混音和音色控件只读，总音量可调。
- 退出比较恢复进入前的快照，保持暂停，避免意外发声。退出不修改任何作品数据。
- 比较期间从作品库选择其他版本，或使用浏览器前进后退，直接结束比较并执行普通版本切换规则，不先播放恢复的快照。
- 不满足条件时禁用对应位置切换，说明具体原因。用户仍可退出比较后分别试听；禁止静默跳到曲首或裁短选区。
- 快速连续切换只采用最后一次选择。旧版音符及效果不得继续混入新版，允许为消除爆音采用短淡出、淡入，不宣称无缝切换。

### 3.6 混音与导出

混音器保留现有静音、独奏、轨道音量和旋律音色。明确显示生效状态；静音优先于独奏，多轨独奏继续有效。增加“恢复本版默认混音”，总音量不随该操作重置。

音色更换作用于声音，不改变音符。其他轨道的音色选择、声像和效果调节在本轮不新增，避免出现界面有控件而音频引擎未支持的情况。

导出菜单区分两种音频：

- **导出当前试听混音 WAV**：导出完整当前版本，采用点击时的乐谱与混音快照；循环和局部选区不改变导出范围。比较模式下导出当前 A 或 B 的原始混音。
- **下载原始成品**：下载该版本已保留的 WAV，不受临时混音影响。

MIDI、JSON 继续导出完整乐谱；MIDI 不承诺保留本项目采样、效果或混音声音。导出期间切歌、切换比较版本或修改选区都不能改变正在导出的内容，进度和完成提示始终带实际导出的版本名。

## 4. 技术实现设计

### 4.1 技术选型与 MuseScore 边界

| 能力 | 本轮选择 | 原因 |
| --- | --- | --- |
| 页面、目录、音乐数据 | TypeScript | 复用现有结构与可重建的乐谱 |
| 播放、循环、离线 WAV | 原生 Web Audio | 已有音色与引擎；可按音频时钟安排播放 |
| 静态构建 | Vite | 现有部署流程可继续使用 |
| MIDI 交换 | @tonejs/midi | 已有导出与往返验证 |
| 音色 | 现有本地采样和合成音色 | 不引入订阅和在线音色依赖；继续保留既有署名 |
| MuseScore | 设计参考，后续交换验证工具 | 接入前需验证导入质量和实际导出能力 |

浏览器内试听和导出保持纯前端。代码创作由当前 coding agent 在项目中完成；本设计没有把 LLM 生成功能放进页面。

后续可通过 MusicXML 向 MuseScore 传递更完整的记谱结构。当前 `Note` 主要描述演奏事件，缺少声部、连音线、休止、符尾分组与谱面拼写等信息，不能把现有 JSON 换个扩展名就当作 MusicXML。现有 MIDI 可以用于初步导入检查，但记谱效果和原网页声音需要分别验证。

如以后要求自动调用 MuseScore，需要本机程序或服务执行；静态网页不能直接替用户启动桌面进程。官方命令行文档提供转换接口，同时注明部分内容沿用旧版本，接入时必须在选定版本上实测。

### 4.2 目录与乐谱数据

采用最小扩展，继续以现有版本 ID 和导出路径作为版本身份：

```ts
type Work = { id: string; title: string; defaultVersionId: string };

// 现有 Song 表示一个独立版本；新增以下目录字段。
type VersionMetadata = {
  workId: string;
  comparisonSections: Record<string, number>;
  // 例：theme: 1，表示共同段落 theme 对应 score.sections[1]。
};

type BeatRange = { startBeat: number; endBeat: number }; // 左闭右开
```

`WORKS` 保存歌曲分组和默认版本，`SONGS` 保留每个版本的作曲入口、说明与文件路径，通过 `workId` 关联。段落对应关系放在目录元数据中，避免为了比较功能重写第一版乐谱 JSON。

注册校验至少覆盖：歌曲和版本 ID 唯一、默认版本存在且属于该歌曲、导出路径独立、对应段落索引有效。同一个共同段落 ID 在一个版本中只允许出现一次；不同再现段落使用不同 ID。

### 4.3 时间与状态

内部音乐位置统一以四分音符拍数表达；秒数仅在音频引擎边界换算：`seconds = beat × 60 / bpm`。内部小节从 0 开始，页面从 1 开始。选区为 `[startBeat, endBeat)`，第 9—12 小节对应 `[32, 48)`，终点上的新音符不属于该选区。

工作台显式管理：当前版本、查看范围、选区、跟随开关、循环状态、播放状态、比较会话。比较会话保留 A/B 版本 ID、当前侧和进入前快照。总音量属于播放器设置；轨道混音属于当前版本的临时试听设置。

切换版本、选区或比较状态必须通过统一操作函数更新引擎和界面，不由多个按钮各自修改零散变量。异步加载和切换继续使用递增请求标识，只允许最新请求启动播放或更新状态。

### 4.4 播放调度

现有引擎每 40 ms 检查一次、预排约 220 ms 音符，适合保留为提前安排声音的机制。循环边界必须依据 `AudioContext.currentTime` 提前安排；不能等页面计时器发现越界后再 `seek()`，否则每一轮都可能出现空隙和节拍漂移。

将“从哪拍开始、何时停止、是否进入下一轮”集中为播放调度规则，由引擎执行。每次跳转、循环修改、暂停或版本切换都使旧的调度代次失效，并取消旧声音、自动音量变化及效果连接。

循环不套用整曲结尾的淡出逻辑；离线整曲导出继续使用原来的尾声处理。实时循环与离线导出共享乐谱、音色和混音定义，但使用独立播放状态。

页面动画只读引擎时间更新游标，不驱动声音。恢复长音沿用现有机制，再以跨边界用例验证攻击声、尾音与叠音。

### 4.5 代码组织

| 位置 | 职责与改动 |
| --- | --- |
| `src/catalog.ts` | 歌曲分组、版本注册、段落对应关系及校验 |
| `src/music/score.ts` | 保留现有乐谱与音符定义 |
| `src/workbench/`（新增） | 作品库、片段视图、比较与混音的交互；相关状态规则和测试放近 |
| `src/audio.ts` | 播放范围、循环调度、旧声音清理；保持独立于页面和版本目录 |
| `src/main.ts` | 页面启动与工作台装配 |
| `src/midi.ts`、`src/wav.ts` | 保持导出格式职责 |

按实际职责拆分；不为缩短文件建立通用状态框架、插件系统或公共工具库。纯计算规则如选区校验、段落映射与时间换算需能脱离浏览器测试。所有试听操作不得写回作曲函数或导出原件。

## 5. 实施顺序与验收

### 5.1 实施顺序

1. **目录与工作台布局**：先写分组、旧地址兼容和切换状态用例，再实现作品库、按需混音和局部视图。
2. **片段与循环**：先明确拍数范围和循环边界的失败用例，再实现音频调度及视图联动。
3. **版本比较**：先覆盖对应关系、条件不满足、暂停与快速切换，再加入 A/B 界面。
4. **整体验证**：保留原件校验，完成浏览器操作、真实音频边界检测和人工试听，再更新项目说明。

以上四步构成本轮完整范围，每一步完成后验证已有播放与导出没有退化。

### 5.2 验收清单

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 原件保留 | 第一版乐谱与原始 JSON 深比较一致；原始 WAV 的 SHA-256 不变 |
| A02 | 多歌曲、多版本 | 用至少两首歌、其中一首两个版本的测试目录验证分组；测试曲允许不同速度与时长，不能硬编码 180 秒 |
| A03 | 地址导航 | 两个旧 hash 仍能直达；刷新不播放；无效地址有提示；前进后退状态一致 |
| A04 | 局部视图 | 第 9—12 小节显示正确音符与和弦；切换四/八小节视图不改变音符或播放位置 |
| A05 | 选择边界 | 反向拖选被规范为有效范围；空选区、越界、曲尾不足四小节得到明确处理；无选择不能启用循环 |
| A06 | 持续循环 | 用已知节拍的测试音频连续循环 20 轮；调度边界误差不累计，目标不超过 10 ms；另检查真实输出无额外音符和异常间隙 |
| A07 | 长音与停止 | 覆盖选区前开始的长音、跨终点音符、循环中暂停/跳转/修改选区；无重复叠音、残留伴奏或持续效果尾音 |
| A08 | 比较位置 | 使用“两个版本段落绝对起点不同、共同段落长度相同”的夹具，验证按段内位置映射，而非复制秒数 |
| A09 | 不可比较 | 缺少对应段落、速度不同、段落长度不同、选区跨段落时禁用比较切换并解释原因 |
| A10 | 比较状态 | 暂停后切换不播放；播放中切换不叠加两版；快速切换最终版本正确；退出恢复进入前状态且暂停 |
| A11 | 混音 | 静音优先、多轨独奏、恢复默认有效；总音量保留；比较时使用原始混音，退出后临时设置可恢复 |
| A12 | 导出隔离 | 循环中导出仍为完整曲；导出途中切歌、切版本、改混音不影响快照；文件名与版本一致 |
| A13 | 加载异常 | 音色加载失败可重试；加载中切换版本后，旧请求不得启动播放或覆盖新版提示 |
| A14 | 桌面与窄屏 | 桌面及 390 px 宽视口完成选曲、选区、循环、比较和导出；无页面横向溢出；键盘可到达控件、焦点可见、状态不只靠颜色 |

循环的实际声音检查使用真实浏览器音频路径；离线调度或模拟时钟测试不能单独证明实时播放正确。浏览器处于前台是本轮实时验收条件，后台节流与系统休眠不承诺连续播放。

现有 `npm test`、`npm run build` 与浏览器验证脚本作为回归入口。保留已有导出快照和音频完整性检查；新增测试覆盖可观察行为，不把组件内部结构当作验收标准。

### 5.3 音乐效果验收

交互和音频技术检查由开发完成；是否好听由实际试听与用户反馈决定。至少用第二版完成三次听评：主题及回答句的连续循环、主旋律独奏与完整编配切换、同一段落的两版比较。

用户应能清楚指出“哪一版、哪一段、哪几小节”需要修改。音符数量、重复次数和文件无削波不能作为“旋律好听”或“符合目标风格”的证明。

## 6. 后续事项与待商榷

| 事项 | 当前决定 | 开始条件 |
| --- | --- | --- |
| 五线谱与 MusicXML | 后续扩展 | 用户需要读谱或进入 MuseScore 修改，再验证休止、声部、连音与谱面导出质量 |
| MuseScore 自动渲染 | 后续独立验证 | 确定桌面程序版本与音源，完成同一片段的导入、播放、导出实测 |
| 更多音色与效果 | 后续扩展 | 按实际听感问题选择音源，核实分发许可、加载成本和效果 |
| 不同速度、不同结构的 A/B | 待商榷 | 先确认比较目的：音乐位置比较或成品声音比较，再设计对齐行为 |
| 试听设置长期保存 | 待商榷 | 当前仅保存运行中的状态；需要刷新后恢复时再明确保存范围 |
| 音符编辑、片段音频导出 | 本轮不实施 | 有明确使用需求后单独设计，避免混入试听和完整作品导出的语义 |
