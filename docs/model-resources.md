# 本机模型与资源

Music Room 用同一个服务管理 Breeze TTS 2、IndexTTS 2.0、YuE2、Seed-VC、参考清理、乐谱合成、调速和安装。模型文件可以同时安装在磁盘上；重型任务逐项执行，结束后确认所属进程退出，再加载下一项。

## 使用

打开首页「设置 → 本机模型与资源」，查看电脑内存、应用上限、系统压力、模型驻留和统一队列。

侧栏优先显示整机内存压力、“本程序可再用约 X GiB”（当前启动预算）和本程序占用。有任务时显示启动预约与运行保护上限；“内存详情”仅列出总内存、程序上限、压缩和交换四项数字。完整采样与预算计算依据见下文及资源状态接口。非空闲包含缓存，接近物理容量不等于内存压力紧张。[Apple 的内存说明](https://support.apple.com/en-au/guide/activity-monitor/actmntr1004/mac)将内存压力与单纯占用量分开。

- **准备模型**：下载或校验文件，进入统一队列；准备完成不表示模型驻留。
- **启用音乐**：允许提交音乐，生成时才加载。停止音乐会取消音乐任务并关闭启用状态；旧音乐仍能播放。
- **暂停后续任务**：当前任务继续，后续任务保留输入排队；恢复后重新检查资源。
- **取消**：等待所属处理停止，保留已保存原音、参考和完成作品。未接收完成的上传不创建作品。
- **释放空闲模型**：只在没有排队或执行任务时操作。
- **预算、安装与诊断**：收紧应用上限，或恢复自动管理。实际额度取所填上限与默认安全额度的较小值；有任务时不能修改。

作品浏览和播放不等待模型队列。音频读取只保留一项完整响应缓冲区，文件有大小和校验限制；浏览器会回收未使用的试听缓存。音频通过有大小上限的字节流建立内存缓存，读取失败可在播放器中“重新读取”。播放仍会占用整机内存，系统压力保护同时覆盖这些占用。

## 当前支持与输入范围

真实模型当前验证于 Apple M4、32 GiB 统一内存、macOS。没有在真实 8 / 16 / 24 / 64 GiB 设备或独立显卡验证；这些容量只用于预算策略模拟。其他平台的模型后端不宣称支持。

| 任务 | 当前固定配置 / 输入范围 | 任务预约 |
| --- | --- | --- |
| 语音（有参考文字稿） | Breeze 4bit / MLX；正文最多 8000 字，每段最多 140 字；参考最长 15 秒 | 5 GB（十进制） |
| 语音（无参考文字稿） | audio.cpp F16 tail2；正文最多 8000 字，串行分段，每段最多 140 字 | 6 GiB |
| 参考清理 | 固定 UVR 模型，CPU；0.3–15 秒 PCM WAV | 8 GiB |
| 音色转换 | 固定 Seed-VC / HTDemucs F16；最多 200 MiB、20 分钟 | 10 GiB |
| 音乐 | 固定 YuE2 MLX 低内存；fast / quality；实际输入加规划和语义生成预留不超过 24576 token | 14 GiB + 每个输入 token 224 KiB 缓存估计 |
| 同步歌词 | Qwen3-ASR-0.6B / ForcedAligner-0.6B 依次运行；最多 10 分钟 | 启动 4 GiB；运行保护最高 8 GiB，不预占 |
| 乐谱合成 / 调速 | 来源最多 10 分钟；调速 0.5–2.0 倍；受支持声道和采样率 | 512 MiB 固定开销 + 随长度增加的缓冲区 |
| 上传导入 | 最多 200 MiB；获准后才读取请求内容 | 64 MiB + 最大输入的三倍 |
| 安装、下载、解压和校验 | 原有固定程序及模型安装路径 | 1 GiB，另查磁盘余量 |

Breeze 的正式服务短句、两段长稿及 14.63 秒合成参考边界测试见[接入记录](testing/verification-breeze-integration-2026-10-26.md)。运行时另检查 Python 进程生命周期峰值，超过 5 GB 停止，不承诺所有输入都能完成；此限制不涵盖旧 IndexTTS 或参考清理。

这是完整任务的保守预约，包含加载、运行时和后处理，不是模型权重大小或实测峰值。音乐使用已安装的真实分词器检查完整请求；原来的风格 1000 字、歌词 2000 字门槛已移除。额外缓存按 28 层 × 8 个 KV 头 × 128 维 × K/V × BF16 两字节 × 两个 CFG 分支计算。这是容量估计，不声称所有接近上下文上限的输入都已实测；运行时内存与压力保护仍独立执行。模型、程序、依赖身份改变后旧档案不自动放行。未验证输入会保存失败原因，不自动减精度、分段或反复重启。

启动预约（`demand.startup`）与请求的运行保护上限（`demand.peak`）为独立字段。同步歌词按[本机实测](evidence/lyrics-memory-calibration-2026-10-22.json)及用户选择，使用 4 GiB 启动预约、最高 8 GiB 运行保护；保护上限不预占内存，也不要求启动预算达到该值。其他固定引擎仍沿用原有保守数值，两者相同。旧调用未提供 `startup` 时按完整保护上限预约。运行上限还受应用额度及已有占用约束，实际生效值通过执行上下文和任务准入明细提供。

网页添加参考声音只接受 **50 MiB 以内、10 分钟以内的单声道/立体声未压缩 PCM WAV**，再提取最多 15 秒。压缩音频、视频和更长录音需要先导出 WAV 人声片段，避免浏览器先将整个大文件解码进内存。此限制不改变音色转换原音格式或已有作品播放。

## 电脑能否运行

默认系统保留量为 `max(物理容量 × 30%, 2 GiB)`，当前可用量另留 1 GiB；应用其他占用、用户上限和系统压力也参与判断。交换空间不算可分配容量。统一内存只有一个池，独立显存的策略逐池检查，不相加。

应用已有占用统计主服务及其存活后代，包含模型子进程；运行保护仍以主服务基线计算任务占用，不因启动前已有模型而漏记。macOS 原生采样读取内核页计数及交换占用、累计换入和换出；`memory_pressure -Q` 的百分比仍作为系统可用估计，乘以物理容量后得到估计量，不是模型可用量的保证。超出实际空闲的部分仅标为可回收程度不确定；不把全部非活动页、文件后备页或压缩占用加进预算，各类别可能重叠。

```text
应用上限 = min(物理容量 − 系统保留量, 平台上限, 用户上限)
当前启动预算 = max(0, min(应用上限 − 本程序已有占用, 系统可用估计 − 额外余量))
还需新增的预约 = max(0, 启动预约 − 可复用的模型驻留)
```

这些是估计依据，不是对真实峰值的承诺。压力偏高时即使账面预算够也会等待。准入结果包含预约、预算、差额与限制来源，区分用户上限、物理/平台容量、本程序已有占用、系统当前资源和压力；指标读取失败单独报告，不当作零占用或内存不足。

| 物理内存 | 仅按容量算的应用上限 | 容量策略结论，不是真机承诺 |
| --- | --- | --- |
| 8 GiB | 5.6 GiB | Breeze 可能获准，仍受应用占用和当前可用量限制；IndexTTS、音乐、转换及参考清理不能按现有预约准入 |
| 16 GiB | 11.2 GiB | 语音/参考/转换可能获准；音乐至少 14 GiB 的预约不能获准 |
| 24 GiB | 16.8 GiB | 四类任务可能获准，仍须扣除应用占用并检查动态可用量 |
| 32 GiB | 22.4 GiB | 本机已实测；同时有其他大程序时仍可能等待或被拒绝 |
| 64 GiB | 44.8 GiB | 策略模拟通过；仍逐项执行，不自动并行加载模型 |

容量不够会在加载前拒绝。临时内存不足或另一个工作区正在使用模型时等待；默认取得队首后最多等 60 秒，失败后由用户明确重试。暂停的后续队列不计入这个等待窗口。

## 运行保护与恢复

约每秒通过 macOS `proc_pid_rusage` 读取所属进程组 physical footprint（内嵌原生监测程序，不扫描 VM 映射），并观察主服务新增占用、系统压力和交换计数。超运行保护上限、危险压力、系统压力偏高且交换占用或累计换出相对开始增加 512 MiB、或指标读取失败时停止任务，确认退出后才交还执行权。已有但稳定的交换占用不单独触发停止；占用不变但持续换出且压力偏高仍触发保护。监测读取失败时保留原始错误供技术详情追查。系统压力正常且任务未超预算时，整机交换变化不会单独触发停止。**采样不是瞬时硬上限**；其他应用或旧版服务也可能占用电脑资源。

运行监测只查询已经登记的模型进程组，避免无关程序频繁创建 / 退出进程时，其不完整行影响本任务。尚无模型进程组时仅测主服务；已退出的空进程组按 BSD `ps` 的无输出退出状态识别。目标进程组格式异常、权限失败及连续采样超时仍停止任务，不把未知状态当作零占用。

同用户的新版服务通过用户级租约互斥，适用于不同工作目录。进程归属按 PID、启动身份和进程组确认；不按名字清理别人进程。服务被强制杀死时监管进程停止模型后代；重启确认后代退出后恢复租约。中断任务保留输入，用户明确重试，不自动恢复推理。

安装、下载失败保留可恢复的已有文件；产物校验或释放失败不会假报完成。无法确认释放时停止后续重型工作，需要检查诊断并重启服务。损坏预算设置只阻止重型任务，可恢复自动管理；作品库仍打开。

目前采用单重型任务限制 CPU / 下载并发；没有声明 CPU 百分比硬限额，也未完成其他平台的运行监控适配。安装来源、账号、发布签名等上线事项不作为开发或上述本机功能的启动条件。

## 接口与证据

网页、HTTP `/api/<操作名>` 和 MCP 共用 `resource_status`、`resource_pause`、`resource_resume`、`resource_cancel`（taskId）、`resource_release`、`resource_set_limit`（memoryBytes 或 null）。查询区分估计额度与采样占用；不触发模型加载。旧业务任务状态继续保留，资源原因在子状态中提供。

- [设计](design/model-resource-management.md)规定边界；[开发计划](design/model-resource-management-plan.md)规定实施顺序。
- [逐轮开发记录](design/model-resource-development.md)记录 TDD、review、修复和每轮提交。
- [独立二进制与异常验收](design/model-resource-binary-evidence.json)记录最终程序 SHA、页面回归与真实取消/强杀/重启。
- [固定引擎实测](design/model-resource-evidence.json)保存版本、输入、采样峰值及负例；本机原始音频位于 `test-results/resources-real/`。
- 普通回归：`npm run test:service`、`npm test`、`npm run verify:resources`。不下载或加载真实模型。
- 独立二进制：`npm run build:binary && npm run verify:binary`，移走松散资源并移除 PATH 中的 Node/Bun 验证。
- 已有固定安装的受控标定：`npm run verify:resources:real`；支持指定 `MUSIC_ROOM_TTS_SOURCE/YUE_SOURCE/CONVERSION_SOURCE`，克隆到隔离目录。
- 已有隔离安装的真实二进制与异常验收：`MUSIC_ROOM_RESOURCE_RUN=<隔离安装目录> npm run verify:resources:binary:real`。不使用放行测试硬件的生产开关。

- [内存口径与启动预算回归](evidence/resource-budget-clarity-2026-10-22.json)记录原生采样、独立启动/运行预算、进程退出确认、页面验证与本机安装；全量服务测试有两项受本机磁盘余量阻塞。

- [Chrome 播放读取修复](evidence/playback-blob-read-2026-10-22.json)记录原浏览器对照试验、播放与重试验证，以及扩展回归的未通过项。
