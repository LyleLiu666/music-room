# 固定语料与真实听评

语料定义为 `tests/quality/cases.json`。9 组覆盖普通 / 数字混读 / 长段语音、纯音乐 / 带重复副歌的歌曲、干声 / 带背景音的转换、三档变速、实际唱词与同步。模型效果必须由真实产物证明。

## 准备与生成

1. `npm run prepare:quality` 生成 `test-results/quality/corpus.json`、受控人声背景混音和 `review-template.json`。输入和产物都有 SHA-256。准备过程不调用模型、不联网、不把模板标成通过。
   可用 `MUSIC_ROOM_QUALITY_REAL=1 MUSIC_ROOM_RESOURCE_RUN=/绝对路径/隔离模型 npm run verify:quality:real` 执行固定生成。大模型组要求本机可用空间至少 10 GiB；变速组使用自己的实际磁盘和内存预算。结果写入 `test-results/quality/real/execution.json`，逐次保留失败记录，重跑时复用成功音频。`MUSIC_ROOM_QUALITY_CASES` 可显式指定逗号分隔的用例编号；报告同时列出本次范围和全部生成样本的状态。客观波形分析不会填写人工评分，也不会生成虚假的歌词人工真值。
   同一执行目录用于同一份固定语料和同一组模型。变更输入、模型或需要重新验收的生成行为时，使用新的 `MUSIC_ROOM_QUALITY_RUN=/绝对路径/新执行目录`。续跑会先校验准备时的输入指纹、模型记录、请求与种子 / 速率、已有音频哈希和非空日志；新生成记录另带日志哈希。来源变化或文件损坏直接失败，不静默覆盖旧证据。早期记录未保存日志哈希时不补造历史值，最终留档记录本次核验值。续跑检查仍不能替代最终质量门禁与人工听评。
2. 复制模板为 `review.json`。记录代码提交及工作差异、OS / CPU / 内存、模型权重版本和实际配置、浏览器版本。使用独立工作目录；不在用户项目里生成测试结果。
3. 按目录内每组 `input` 原样输入正式产品。Q-TTS-03 将正文重复 30 次，保留句号；不改成 30 个独立生成任务。TTS / 音乐固定种子 42、43、44 各一次；不挑最好的一次隐藏失败。若模型不暴露种子，注明不可控，并保留三次完整输入输出记录。
4. TTS 用 `official.wav` 参考。转换用固定源文件和 `tianjin.wav` 目标音色；Q-SVC-02 用准备脚本生成的 `prepared/voice-with-background.wav`，对完整时间线检查。此受控混音不等价于真实复杂歌曲，发布时还需真实使用素材抽样。
5. Q-SPEED-01 从同一原音分别保存 0.5、0.8、2.0 倍音频。对比正式保存版，不能拿浏览器即时变速试听替代。
6. Q-LYRICS-01 使用 Q-MUSIC-02 的真实演唱，先由听评人独立转写实际听见的内容，再和系统结果比较。参考歌词仅用于核对，不作为“实际唱出了这些词”的证据。
7. 记录音频、完整推理日志、原始请求、错误与取消结果；Q-LYRICS-01 另存独立人工文本及逐句起点。只记录必要的模型和运行信息，不记录云访问令牌。

## 评分与失败标准

每个样本听开头、所有分段接缝和最后 10 秒，再完整听一遍。多个种子 / 速率分别评分，组得分取最低值，禁止用均分掩盖丢句或爆音。

| 维度 | 4 分及以上的要求 | 阻断情形 |
| --- | --- | --- |
| clarity | 语音 / 歌词可理解；器乐主题清楚 | 漏掉重要正文、数字含义错、持续无法理解 |
| continuity | 音色、节奏、声道连续；变化符合输入 | 明显接缝、突变、声道丢失、转换时间线错位 |
| completeness | 所有正文、主要段落及结尾完整 | 提前硬切、重复循环、缺段、丢掉原背景时间线 |
| noArtifacts | 无明显削波、金属感、异常静音 | 爆音、明显损坏、持续失真或非预期静音 |

5 分为无可辨认问题；4 分为有轻微瑕疵但不影响上述要求；3 分及以下为不通过。每组四项均至少 4/5，且无 `blocker` / `major` 缺陷。模型目标时长允许自然偏差，偏差必须记录；不能以“最后有声音”判断收尾合格。

歌词字符准确率采用 `max(0, 1 - (替换 + 删除 + 插入) / 人工真值字符数)`；只忽略标点和空白，保留重复句与顺序。阈值 0.95。将系统每句起点与人工起点配对，绝对误差 p95 不超过 0.5 秒；缺句、幻觉句不能从分母里删除。不确定唱词要记录为待核对，不能用参考词补成已确认内容。

## 证据格式与门禁

复制模板后逐项填真实结果。每项包含 `caseId`、`status`、`reviewedBy`、ISO 时间 `reviewedAt`、四项 `scores`、`findings` 和 `artifacts`。每个 artifact 包含相对 `review.json` 的路径、`kind` 和文件 SHA-256；音频类型为 `audio`，日志为 `inference-log`，歌词真值为 `human-transcript`。TTS / 音乐三次试验的音频及日志分别标记数值 `run: 1`、`2`、`3`，附上实际 `seed`；门禁不接受只交最好的一次。变速音频附加数值 `rate`。歌词指标填写 `metrics.characterAccuracy` 与 `metrics.startErrorP95Seconds`。

```sh
npm run verify:quality -- /绝对路径/review.json
```

门禁检查结果齐全、真实推理声明、听评记录、分数、阻断缺陷及产物哈希。它不能自动证明听感好，也不能鉴别伪造的人类评分。执行者必须实事求是；默认模板、缺失文件、待评结果、失败结果不能通过。合成音频在单元测试中验证门禁逻辑，不计入真实听评结果。
