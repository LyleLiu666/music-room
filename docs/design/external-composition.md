# 外部创作与本机作品库

状态：已实现；验证依据见文末。格式的唯一说明是 [独立创作包 README](../../src/music/authoring/README.md)，不在设计文档重复字段定义。

## 1. 使用方式

Music Room 是静态试听工作台。Agent 用任意语言运行作曲代码，交付 MIDI 或创作 JSON；用户导入文件，在浏览器本机听音色、调整混音、导出音频。Agent 不需要项目源码。页面不运行外部脚本，不调用在线模型，不上传作品。

作品按创作项目分组，一首作品拥有多个不可覆盖的版本：

1. 展开作品库中的“让 agent 创作新曲子”，选择“先写 4 小节”或“先写 8 小节”。
2. 下载独立创作包，复制提示词，交给 agent；拿到文件后点击“导入 MIDI / JSON”或把单个文件拖入导入区域。
3. 试听 riff、回答句、律动和音色，给出反馈。修改仍然交付新版本，旧版保留。
4. 对满意的版本选择“扩写当前版本”，下载当前版本 JSON，把乐谱和扩写提示词一起交给 agent。
5. Agent 沿用作品身份，创建新版本；导入后和草稿归在同一个项目。可继续到完整编曲。

四小节或八小节应形成完整乐句，不要求用户先完成三分钟作品。版本时长可不同；A/B 仍要求同速度、明确对应且等长的段落。扩写时保留已认可的短片段为单独段落，才能与原片段比较；没有对应段落时解释原因，仍能分别试听。

页面提供可编辑提示词、完整示例、创作说明、独立校验器 ZIP。ZIP 中只有说明、提示词、示例、两个 JavaScript 文件；从空目录使用 Node.js 运行校验，不依赖项目包或源码。页面提示词按明确选择的步骤生成，扩写时附带当前作品 ID、版本 ID、小节数、速度和附件文件名；不猜测自然语言意图。

## 2. 数据与文件

- `work.id` 是创作项目身份，`revision.id` 是某次版本身份；标题不用于猜测分组。相同项目标题必须一致，版本 ID 全库唯一。导入冲突直接拒绝，不覆盖。
- JSON 包含作品、版本、段落、和弦与音符。页面下载的 JSON 使用独立契约；旧 `public/exports/` 中原始乐谱与音频原样保存。
- MIDI 根据明确 GM 协议映射到现有音色，未知音色报错。普通 MIDI 导入为独立项目；后续下载该版本 JSON，再沿用项目 ID 创建新版本。
- MIDI 不恢复原文件的踏板、弯音、表情、混音与效果，不保留段落和和弦；页面与说明显式告知。JSON 更适合工程和版本保存，MIDI 用于演奏交换。
- MIDI、JSON、作曲源码、WAV 的持久备份由用户保存在电脑；浏览器额外保存导入乐谱副本，方便刷新后继续。站点地址或浏览器不同、副本清理都可能使页面库不同，没有云端同步。
- 本机最多 50 个导入版本，保存采用先写存储后更新内存。存储满或不可用时导入/移除失败，当前作品库保持不变。坏文件、重复版本和不支持的 MIDI 不会停止当前播放。
- 移除只作用于浏览器副本，不改动电脑上的源文件；可重新导入备份恢复。内置版本不可移除，原始成品下载仅对内置版本显示。

## 3. 实现边界

| 文件 | 职责 |
| --- | --- |
| `src/music/authoring/` | 独立格式、共享校验实现、声明、完整示例、说明与提示词 |
| `src/music/import/library.ts` | 本机存储、项目与版本身份、事务保存、移除和坏数据恢复 |
| `src/music/import/midi.ts` | GM 音色/鼓音的确定性映射、固定速度和 4/4 检查、转换到同一契约 |
| `src/workbench/app.ts` | 文件选择、导入状态、作品库更新、文件下载及提示词步骤 |
| `scripts/build-authoring-kit.mjs` | 从唯一源目录生成可下载创作包和 ZIP；生成文件不进 Git |

契约限制：单文件 4 MiB、20,000 音符、最多 256 个同时持续音符、最多 512 小节/600 秒、固定 4/4、40—240 BPM、现有 11 音轨。校验包括字段与数值、连续段落、小节归属、曲内音符边界、共同段落索引以及未知字段。导入排序音符，以满足播放调度要求。外部文本显示为文本，不作为 HTML 或样式执行。

MIDI 格式 0/1 可用，独立序列格式 2 和 SMPTE 时间不支持。JSON 是唯一完整保存本工作台版本和段落的交换格式；没有把音符检查当作音乐审美检查。

后续范围：音符编辑、任意脚本执行、云端生成与同步、任意 MIDI 音源及控制器还原，不是当前开发门槛。

## 4. 验证

单元测试 `tests/import.test.ts` 覆盖契约边界、音轨契约与引擎一致、存储事务、身份与分组、MIDI 音符往返、原作品 MIDI/JSON 可交换、短乐句与扩写提示词。原作品 JSON 深比较与 WAV 哈希继续由原测试保护。

真实 Chrome 脚本 `scripts/verify-imports.mjs` 验证：

- ZIP 解压到独立临时目录，不依赖源码或 npm 包运行校验；错误文件返回失败。
- JSON 实际播放通过 AudioWorklet 录音测得非零声音，20 秒完整双声道 WAV 有波形，MIDI 与 JSON 下载可再导入。
- 两版归组、不同长度扩写、等长原片段 A/B、刷新暂停、前进后退、移除与备份恢复。
- 错文件保持当前播放、重复 ID 拒绝、存储失败不添加幽灵版本。
- 导入文本不能执行 HTML，长标题不撑宽 390 px 页面，拖拽高亮/完成复原及多文件拒绝有效；提示词可修改复制，包可下载。

与此前工作台、实时循环、比较、加载边界、完整 180 秒 WAV 一同运行 `npm run verify:all`。报告和截图位于忽略提交的 `test-results/imports/`。技术通过后仍由用户试听判断曲子好不好听。
