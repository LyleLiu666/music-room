# audio.cpp F16 推理引擎

当前调度与支持范围见[本机模型与资源](model-resources.md)。下面的常驻复用、Python/MLX 对照和旧内存实验是历史证据；当前服务每项任务后确认卸载，未验证后端/输入不能作为自动回退放行。


## 当前运行方式

Apple Silicon 的默认 TTS 后端为 audio.cpp 0.9.1-music-room-tail2 / Metal / IndexTTS 2.0 F16 GGUF。模型、参考 WAV、情绪描述与版本数据沿用现有项目流程。五个内置音色和自定义干人声都由同一引擎处理；原 NPZ 特征仅供旧 Python 后端使用。

第一条生成启动一个原生常驻服务，后续正常任务复用同一模型与推理会话。Music Room 的语音队列仍为 FIFO，同一时刻只有一个生成任务；没有开启实验性并行会话。`idle_unload_ms=0`，正常完成与空闲均不卸载模型。`mem_saver=true` 回收阶段性计算图，参考、参考情绪与情绪文本缓存各保留最近一项。

原生服务仅绑定随机的本机回环端口，不开放 UI、模型管理或 CORS。Music Room 经内部接口调用它，音频校验后才发布为正式版本。用户继续使用原网页和 MCP 接口。

## 请求参数隔离

每条任务发送独立、完整的情绪控制。新创作默认「情绪一般」，按用户试听反馈，五个档位「情绪非常平淡 / 情绪平淡 / 情绪一般 / 情绪强烈 / 情绪非常强烈」对应 0.03 / 0.1 / 0.3 / 0.6 / 1.0；两个新低档 0.03 / 0.1 为试听候选，默认一般采用原平淡的 0.3；数值不在页面展示。描述指定情绪类型，强度调节表现程度，两者分别保存到草稿和生成版本。

显式选择强度且描述留空时，原生引擎将模型已有的第八组平静情绪与参考人声情绪按强度混合；使用模型原有的说话风格近邻选择。强度 1 精确沿用参考向量，混合不修改参考缓存。旧版本没有强度字段时不启用此处理，继续采用原参数：有描述 0.6，留空 1。「修改这版」保留历史缺字段，只有用户明确选择档位才写入新设置。低强度不保证中性，高强度不保证高亢。

描述留空时显式关闭文本情绪并清空描述，随机情绪关闭。情绪缓存按完整描述区分；请求强度不沿用上一次任务。测试覆盖五档、留空描述、历史缺字段、连续切换、草稿与版本重启恢复，以及 Python 兼容入口。

新版本入队前生成并保存 `seed`（0–4294967295），原生及 Python 驱动均显式使用该种子。`tts_generate` 可传入原种子用于诊断复现；保持模型、参考音频、参数与运行环境一致。旧版本未保存种子的，不补造历史值。本机已验证相同种子的连续两次生成 WAV 完全一致，且复用同一常驻进程；不承诺跨设备或升级后的逐字节复现。

## 生命周期与取消

Music Room 持有监督进程的 stdin 租约；服务退出或租约消失时，监督进程结束所属原生进程组。原生计算进程不会在网页关闭时退出。

取消排队任务不触碰当前引擎。取消正在运行的任务会结束当前原生进程，必要时强制停止；只有确认停止后才允许下一条重建引擎。断开 HTTP 请求并不能保证 GPU 计算取消，因此不把连接中断当作计算已停止。

原生进程崩溃、安装目录切换和独立人声清理也会重建引擎。清理前暂停常驻 TTS，完成清理后的首次生成重新加载。正常生成不触发回收。音乐和 TTS 尚无统一内存调度，联合运行占用不能用单个 TTS 的结果保证。

## 固定安装与数据保留

- 程序：基于 audio.cpp v0.9.1 的 `0.9.1-music-room-tail2`，macOS arm64 Metal；源码、补丁和程序包 SHA-256 记录在 `src/service/tts/native-program-manifest.ts`。独立二进制内置约 6.6 MB 程序包，安装先校验内置包；开发模式无内置资源时使用固定哈希下载。构建方法见 [原生补丁说明](../native/audio-cpp/README.md)。
- 模型：`audio-cpp/audio.cpp-gguf` 快照 `a199f1a00ae893af0067caeab51f810de4c728a5`，`index-tts2-f16.gguf`，4,646,898,304 字节，SHA-256 `0f7b95d3d32e18bf9352912a7b21a0bd4a8406853a0aaa2c9180f77389c21523`。
- 文件：`~/Music/IndexTTS2/audio-cpp/{release,models,installed.json}`。下载直接流式写盘，校验后发布安装记录；中断下载可续传。
- 现有 Python 环境、模型、历史语音版本、参考原音和已保存 WAV 保留。新版本额外记录 `backend=audio.cpp F16`。

## 实测与边界

**收尾修复已通过指定样本的用户试听：结尾自然，中间正常。** 新引擎在声学生成时提供空白收尾上下文，波形还原时提供静音上下文，保留额外自然尾音；文本与 GPT 语音编码保持原值。模型精度仍为 F16。定位、未采用方案及效果边界见[短句收尾与停顿对照](tts-prosody-test-2026-10-09.md)。下面迁移初期的数据仅作历史对照，修复版实测另列。

修复版实测：正式 `SpeechService` 与原生驱动在隔离工作目录连续成功生成 9 条音频，覆盖四个内置音色、情绪开启后留空、108 字长文、空闲后继续与取消后恢复。前 8 条正常任务共用 PID `1626`；仅取消运行中的任务后重建为 PID `4059`。相同种子的留空情绪音频在切换音色、情绪及空闲后仍逐字节一致，排队取消不重载当前模型。物理峰值约 **4.9 GiB**，长文完成后约 **4.7 GiB**；长文生成 70.70 秒、音频 22.27 秒，同参考短句复用生成约 18.97 秒。新增声学上下文有额外计算，本轮不是严格速度 A/B，不报告零耗时影响。69 项服务测试、构建及 12 项独立二进制检查通过；安装包中的原生程序哈希已验证。记录为本机 `tail-resident-result.json`、`tail-resident-samples.json`、`tail-resident.log`。

正式独立服务已切换到修复版，连续两条种子 42 的真实生成均成功，WAV 逐字节一致，且与隔离回归的同输入产物完全一致。两条任务复用 PID `4327`，完成后继续常驻；本轮短句物理峰值约 **4.2 GiB**，完成后约 **4.1 GiB**。音频接口返回内容与保存文件哈希一致。升级前的 24 个版本、22 份音频、音色、声音项目及成品选择全部保持一致。记录为本机 `test-results/audio-cpp-trial/tail-production-result.json`。

情绪强度初版实测（当时三个档位为 0.3 / 0.6 / 1）：隔离工作区在同一原生进程连续完成 8 条真实推理，包含无强度历史请求、留空描述三档、「开心、活泼」三档和历史请求重放；正文、迪丽热巴音色、随机种子 42 均相同。两个三档组分别得到三个不同的 WAV。前后历史请求及留空「强烈」与 tail1 既有样本逐字节一致，未发现混合修改缓存或连续任务残留。8 条任务共用 PID `13761`，正常完成未卸载模型，物理峰值约 **4.8 GiB**；首次含加载约 44.53 秒，常驻后各条约 17.17–25.84 秒。此组不是严格速度基准，也不证明听感按数值线性变化。记录为本机 `test-results/emotion-strength/result.json` 与 `native.log`，六份试听音频同目录保存；用户后续确认 0.3 更接近一般、0.6 已强烈，因此保持已有 ID 的实际值，只调整名称和新默认，并增加 0.1 低档。

最终独立程序另在隔离工作区连续提交沈腾与迪丽热巴两条当时的「情绪一般」（0.6，现称「情绪强烈」）任务，严格串行、共用 PID `16722`，完成及空闲后模型保持常驻；迪丽热巴样本与源码驱动对照逐字节一致。五个内置音色的 WAV / NPZ 均通过嵌入包哈希校验与重启 ID 保持验证；88 项服务测试、7 项网页回归和 12 项独立程序检查通过。记录为本机 `test-results/emotion-strength/compiled-result.json` 与 `test-results/binary/verification.json`。

档位校准实测：新低档 0.1 与原低档 0.3 在留空描述和「开心、活泼」两种输入下连续成功生成 4 条真实音频，同文、同音色、种子 42、共用 PID `19106`。原低档两段均与初版对应 WAV 逐字节一致；新低档生成不同音频，待用户试听。36 项强度、驱动、队列与兼容回归及网页草稿/重启测试通过。记录为本机 `test-results/emotion-calibration-2026-10-09/result.json`。随后最终独立程序连续提交两条「非常平淡」0.03 的真实任务（留空 / 开心描述），共用 PID `20275`，生成成功且完整保存设置；最终五档网页回归和 12 项独立程序检查通过。记录为该目录下 `very-flat/compiled-result.json`。

以上实测硬件为 Apple M4 / 32 GiB，仅覆盖指定输入。尚未在真实 16 GB 电脑验收；任意长文、联合音乐生成及无限次运行的内存上限不能用该结果保证。迁移初期的真实队列记录保存在本机 `project-resident-result.json` 与 `production-native-result.json`；该次原生迁移验收以 `tail-*` 记录为准；资源保护最新验收见 design/model-resource-evidence.json。听感由用户确认，WAV 格式检查不替代音质判断。

## 历史回退记录

当前统一资源版本保留 Python 驱动，但其新推理没有验证档案，会在加载前拒绝；下列环境变量不绕过资源保护。确需恢复旧实现，需使用经过验证的历史源码版本。

迁移前源码已提交并推送：`5559685`，标签 `codex/pre-audio-cpp-20261009`。

保留旧 Python 驱动，可停止服务后用以下方式启动同一工作目录：

```sh
MUSIC_ROOM_TTS_BACKEND=python ./release/music-room serve --workspace /Users/liu_y/Music/MusicRoom --port 5174
```

已有服务会被复用，所以必须先停止旧服务再切换环境变量。需要回退源码时，从上述标签建立独立 checkout，构建并验证后再切换服务；避免覆盖当前未提交工作。
