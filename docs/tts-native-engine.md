# audio.cpp F16 推理引擎

## 当前运行方式

Apple Silicon 的默认 TTS 后端为 audio.cpp 0.9.1 / Metal / IndexTTS 2.0 F16 GGUF。模型、参考 WAV、情绪描述与版本数据沿用现有项目流程。四个内置音色和自定义干人声都由同一引擎处理；原 NPZ 特征仅供旧 Python 后端使用。

第一条生成启动一个原生常驻服务，后续正常任务复用同一模型与推理会话。Music Room 的语音队列仍为 FIFO，同一时刻只有一个生成任务；没有开启实验性并行会话。`idle_unload_ms=0`，正常完成与空闲均不卸载模型。`mem_saver=true` 回收阶段性计算图，参考、参考情绪与情绪文本缓存各保留最近一项。

原生服务仅绑定随机的本机回环端口，不开放 UI、模型管理或 CORS。Music Room 经内部接口调用它，音频校验后才发布为正式版本。用户继续使用原网页和 MCP 接口。

## 请求参数隔离

每条任务发送独立、完整的情绪控制：有描述时启用文本情绪、强度 0.6；留空时显式关闭文本情绪、清空描述并恢复参考情绪强度 1，随机情绪关闭。情绪缓存按完整描述区分，不能按上次使用的条目代替当前描述。代码检查暂未确认历史版本存在串用情绪的缺陷；留空本来会沿用参考人声的情绪，不能等同于强制中性。回归覆盖“开心 → 留空 → 平静”在同一进程中的请求字段隔离。

## 生命周期与取消

Music Room 持有监督进程的 stdin 租约；服务退出或租约消失时，监督进程结束所属原生进程组。原生计算进程不会在网页关闭时退出。

取消排队任务不触碰当前引擎。取消正在运行的任务会结束当前原生进程，必要时强制停止；只有确认停止后才允许下一条重建引擎。断开 HTTP 请求并不能保证 GPU 计算取消，因此不把连接中断当作计算已停止。

原生进程崩溃、安装目录切换和独立人声清理也会重建引擎。清理前暂停常驻 TTS，完成清理后的首次生成重新加载。正常生成不触发回收。音乐和 TTS 尚无统一内存调度，联合运行占用不能用单个 TTS 的结果保证。

## 实测与边界

**声音质量仍有未解决问题：**用户试听指出迪丽热巴样本约 2 秒处及句尾有“掐断感”。一路与三路候选的对照未解决共同的句尾问题；这次反馈不改变下述内存、队列和文件验证结果，但声音质量不能据此报告通过。定位与试听记录见[短句收尾与停顿对照](tts-prosody-test-2026-10-09.md)。

2026-10-09，Apple M4、32 GiB。本机原生服务已连续三次生成相同的用户短句和情绪，复用同一进程，后两次生成耗时约 18.63/17.81 秒；实测物理占用约 4.7–4.8 GiB。参考缓存复用与完成后保持模型加载均已核对。记录位于本机 `test-results/audio-cpp-trial/resident-proof*`。

通过正式 `SpeechService` 和原生驱动，在隔离项目中同时提交六条任务，覆盖四个音色、重复音色/情绪及 108 字长文；空闲后再提交一条，七条均复用同一引擎 PID。常驻进程物理峰值约 **4.9 GiB**，长文输出 21.54 秒，空闲后占用约 **4.8 GiB**。取消第八条运行中的长文后确认旧 PID 已退出，随后恢复任务成功；共八条成功音频及一条取消任务。长文约 66.76 秒，同情绪的第二条短句约 17.26 秒，首条含引擎启动约 49.62 秒；这些是指定样本耗时，没有严格的后端速度 A/B 结论。记录为 `project-resident-result.json`、`project-resident-samples.json`、`project-resident.log`。以上是指定输入和本机硬件结果，尚未在真实 16 GB 硬件验收，也不能证明任意长文、联合音乐生成或无限次运行的内存上限。听感由用户试听确认；WAV 格式检查不替代音质判断。

正式工作目录已切换到最新独立二进制，连续提交两条实推理任务（文本情绪开启后留空），均成功并复用 PID `83594`；完成及空闲后进程仍存在，本轮物理峰值约 4.8 GiB。网页播放、下载字节和保存文件校验通过。切换前的 20 个语音版本、18 个音频文件、音色及成品选择全部保持一致。记录为本机 `test-results/audio-cpp-trial/production-native-result.json`。67 项服务测试、TypeScript/Vite 构建及独立二进制检查通过。

## 回退

迁移前源码已提交并推送：`5559685`，标签 `codex/pre-audio-cpp-20261009`。

保留旧 Python 驱动，可停止服务后用以下方式启动同一工作目录：

```sh
MUSIC_ROOM_TTS_BACKEND=python ./release/music-room serve --workspace /Users/liu_y/Music/MusicRoom --port 5174
```

已有服务会被复用，所以必须先停止旧服务再切换环境变量。需要回退源码时，从上述标签建立独立 checkout，构建并验证后再切换服务；避免覆盖当前未提交工作。
